# 检测语义方案 · 对话碰撞 & 主角私心驱动（Item 1）

> 起草：方案方（2026-08-27）。落地：代码方。
> 背景：#65 铁则二十一落地后，生成侧已强制「对话有火花 / 主角有私心」，但**检测侧无对应 ruleId**（仅 `dialogue_overload` 查占比、`character_voice` 查声音漂移，均不查碰撞张力 / 私心动机）。
> 等长复验（§七）进一步暴露：当前 `对话缺乏碰撞` 检测器依赖引号才能识别对话，对无引号风格（引擎真实可能输出）是盲区。本方案补这两个检测器，使"读者爽点"从生成自觉升级为门禁可拦。

---

## 一、dialogue_collision（对话碰撞检测器）

### 目标
在任一场景内，检测到 ≥2 个不同说话人、且后续轮次存在**反对 / 质疑 / 立场对立**时，判定"对话有碰撞"；若对话量达到阈值却零碰撞，报 `对话缺乏碰撞` 警告。

### 信号定义（长什么样）
- **对话轮次**：说话人 A 说 X，说话人 B 说 Y，Y 对 X 含否定 / 质疑 / 反驳 / 对立立场。
- **碰撞标记词**（opposition markers）：`不 / 没 / 别 / 非 / 错 / 不对 / 不可能 / 凭什么 / 为什么 / 怎么（反问） / 你疯了 / 胡说 / 放屁 / 岂有 / 哪能 / 谁准 / 我反对 / 不行`。
- **合格碰撞**：同一场景内，第 2 个及以后的轮次中至少 1 处含碰撞标记词，且说话人与前轮不同。

### 判定通道：**正则（轮次提取）+ 规则（碰撞计数）**
不依赖引号（修复 §七 盲区）。

**轮次提取正则（候选）**：
```
/(?:^|[\n。！？])\s*([一-龥]{1,4})\s*(?:[\s]*(?:说|道|问|回|喊|叫|低声|沉声|哑声|轻声|冷笑|笑|答|插话|骂|吼|喃喃|嘀咕)[\s]*[：:，,]?)\s*([^。！？\n]{2,50})/g
```
捕获：`$1`=说话人，`$2`=话语。同时兜底无"说"的插话式：`([一-龥]{1,4})[\s]*[：:]\s*([^。！？\n]{2,50})` 及 `([一-龥]{1,4})插话[。]?\s*([^。！？\n]{2,50})`。

**碰撞计数**：对每场（按空行 / 视角切换切分）收集轮次序列，若轮次≥2 且存在跨说话人的 opposition marker → `collision += 1`。

### 阈值
- `dialogue_turns ≥ 4`（确属有对话的章）且 `collision == 0` → 报 `对话缺乏碰撞`（warning）。
- `collision ≥ 1` → 通过。
- `dialogue_turns < 4`（独白 / 内心章）→ 不触发（防独白章假阳性）。

### 防假阳性
- 独白章（轮次<4）豁免。
- opposition marker 须落在**不同说话人**的后续轮次，避免自言自语误判。
- 与现有 `dialogue_overload`（占比≤25%）、`character_voice`（差异化）共存，不冲突。

## 二、protagonist_stakes（主角私心驱动检测器）

### 目标
判定主角是否表达**个人化、利己动机**（家人 / 愧疚 / 恐惧 / 欲望），而非纯执行任务。零私心 → 报 `主角工具人` 警告（铁则二十一①"抗工具人"的门禁化）。

### 信号定义（长什么样）
- 主角说出 / 内心出现：个人牵挂（具体人名如阿苓）、恐惧（怕忘 / 怕失去）、利己抉择（"我为个人才赌得起"）、未竟执念（找人 / 赎罪 / 报）。
- 反面（工具人）：主角只转述指令、执行安排、无个人情绪落点。

### 判定通道：**LLM 语义层（推荐）**
正则太脆（"我"全文高频、私心是语义而非词面）。用一次轻量 LLM 判定：
- 输入：本章全文 + 主角名（取自 kb/config，`林深`）。
- Prompt 草样：
  > 你是网文质检。给定章节与主角名 X。请判断：X 是否表达了**个人化、利己的动机**（如家人牵挂、恐惧、愧疚、个人欲望、未竟执念），而不仅是执行任务？若是，引用 1-2 句原文；若否，回"无"。
- 输出：`无` → 报 `主角工具人`（warning）；否则通过。

**正则兜底（弱，仅作候选，不单独定罪）**：
```
(林深[^。！？]{0,15}(?:怕|想|要|记着|欠|赎|报|为了|因为|赌|阿苓))
```
命中≥1 可作 LLM 的否定证据（降低假阳性），但正式判定以 LLM 为准。

### 阈值
- 主角私心句 `≥ 1` → 通过。
- `== 0` → 报 `主角工具人`（warning）。
- 升级选项（待拍板）：若要把"抗工具人"做成硬约束，可升为 **error 级**触发重写；默认先 warning 观察。

### 防假阳性
- 主角名须取自配置，不硬编码。
- LLM 判定须"引用原句"才计数，避免空判。
- 正则仅作 LLM 的否定证据，不单独定罪。

## 三、架构落点（双树统一）

- **ruleId 新增**：`dialogue_collision`（正则，落 CLI 树 `检测工具/checkers.ts`，并回流 `源码/checks/` 单一源）、`protagonist_stakes`（LLM，落 `源码/checks/` 生成时自检，CLI 树 import）。
- **Thresholds 扩展**（`源码/types.ts`）：新增两个可选字段（参照现有 `notShiErrorMin?` / `maxSmoothnessViolations?` 写法）：
  - `dialogueCollisionMin?`（默认 1）
  - `protagonistStakesMin?`（默认 1）
- **统一管道**：按记忆"CLI 树 import 源码/checks"方向，最终两个 ruleId 以 `源码/checks/` 为单一源，CLI 树复用，避免双树漂移（D1–D6 老坑）。

## 四、验收标准（回归验证）

用 ch29 沙盒（before / after_v2）回归：
- after_v2 应用本方案后，`dialogue_collision` 应判 ≥1（即便无引号也能识别轮次+碰撞）；`protagonist_stakes` 应判 ≥1（阿苓线）。
- before 应用本方案后，`dialogue_collision` 应判 0（纯问答无反对）→ 仍报 `对话缺乏碰撞`；`protagonist_stakes` 应判 0 → 报 `主角工具人`。
- 证明两个检测器能区分 #65 前后，且**不依赖引号**。
