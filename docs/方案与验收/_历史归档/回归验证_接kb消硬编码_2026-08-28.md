# 回归验证 · ② 接 kb 消硬编码主角名（支持多作）· 2026-08-28

> 前置：Item1 检测器（正则 + LLM 语义层）已落地并双轨独立核真身认账（§⑬/§⑮）。
> 本轮按用户"先备份，然后开始"指令，启动 ② 接 kb：把硬编码主角名 `林深` 改为从配置驱动，支持多作品。

## 一、要解决的问题

`检测工具/checkers.ts` 的 `checkProtagonistStakes` 与 `源码/checks/check-dialogue-semantics.ts` 的 LLM 层，均把主角名写死为 `'林深'`。
- 跨作品必误报（非本作章节每章误报 `主角工具人`）；
- 违背"接 kb 配置"方向。
- 关键约束：`threshold_overrides` 是 `Record<string, number>`（compile-kb.ts:84），**只能灌数字阈值，灌不进字符串主角名** → 主角名必须另开字段，且是 per-work（作品级）而非 per-style 配置。

## 二、方案设计（双树各自接配置，不写死）

### CLI 树（验收门禁，本次重点验证路径）
- `检测工具/checkers.ts`
  - `DetectorFn` 类型加可选第 3 参：`(text, stats, protagonistName?) => Violation[]`（其它检测器闭包 `(t,s)=>...` 仍兼容，忽略第 3 参）。
  - `checkProtagonistStakes(text, protagonistName = PROTAGONIST_NAME)`：用入参替换写死常量。
  - 注册闭包 `fn: (t, s, n) => checkProtagonistStakes(t, n)`；执行器 `detector.fn(text, stats, protagonistName)` 透传。
  - `checkChapterGrouped` / `checkChapter` 加 `protagonistName?: string` 形参并下传（**现有调用者不传→undefined→回退 `'林深'`，零回归**）。
- 配置源：`检测工具/project-config.ts` 的 `ProjectEntry` 加 `protagonistName?: string`；`检测工具/check-chapter.ts` 从 `project.json` 读 `projEntry.protagonistName` 并透传进各 `checkChapter(...)` 调用点（4 处）。

### 生成树（LLM 语义层，已冻结，本次仅参数化）
- `源码/checks/check-dialogue-semantics.ts`：`checkDialogueSemantics(text, llm, thresholds?, protagonistName?)`；`const name = protagonistName ?? PROTAGONIST_NAME`；提示词改为 `{{PROTAGONIST}}` 占位符，调用时 `.replace('{{PROTAGONIST}}', name)` 注入；消息体同样用 `name`。
- 配置源：`源码/reflection/types.ts` 的 `ReflectionConfig` 加 `protagonistName?: string`；`源码/types.ts` 的 `MergedConfig` 加 `protagonistName?: string`（可选，供 R1_MERGED_CONFIG 等保持类型完整）。
- 透传：`源码/reflection/engine.ts:592` 调用改为 `checkDialogueSemantics(input.content, this.llm, undefined, this.config.protagonistName)`。

### 默认值与回归安全
- 两处均保留 `const PROTAGONIST_NAME = '林深'` 作为 fallback；**未配置时行为完全不变**。
- 配置落地：`InkWeave/.inkweave/project.json` 的 `裂日` 项加 `"protagonistName": "林深"`——证明管道打通（实际值与旧默认一致，故运行时无感）。
