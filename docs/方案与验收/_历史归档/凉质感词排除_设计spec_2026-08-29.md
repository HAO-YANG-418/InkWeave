# U2 设计 Spec · 「凉」质感词排除（per-project）· 2026-08-29

> 本文件是 U2 的**设计轮**交付（不实现，等代码方拍板）。
> 目的：消解 `texture_variety` 对核心概念词「凉」的误伤（占 13 触发章里 7 章 = 54%）。
> 范围严格限定：仅设计机制 + 落点选型 + 可实施清单，不空调、不扩词、不动 KB 管道。

## 0. 一句话结论

**最优方案 = per-project `excludedTextureWords`（写在 `project.json`），复用 ② 已建立的「`project.json` → `readProjectConfig` → `checkChapter` 参数」通道。**
不动 KB 管道、不碰 `mergeConfig` 隔离、不全局放水；把「凉」作为**裂日项目自己的概念词**声明，CLI 树 `texture_variety` 检测时跳过它。改动约 15 行，全在已验证通道上。

## 1. 落点选型：为什么是 per-project，不是"节点级"

原 U2 讨论叫「凉节点排除词表」，但落点必须修正。三种候选：

| 方案 | 做法 | 判决 | 理由 |
|---|---|---|---|
| **A per-project（选）** | `project.json` 加 `excludedTextureWords: ["凉"]`，经 ② 通道透传 CLI 树 | ✅ **最优** | 复用已验证通道、零新架构、per-work 正确粒度、不破隔离、回滚零成本 |
| B KB 节点级 | 在 KB 节点 schema 加 `excludedTextures`，喂 CLI 树 | ❌ 否决 | CLI 树**从不读 KB**（`检测工具/check-chapter.ts:28` 故意不 `import mergeConfig`/`kb-loader`）；要喂就得破隔离 → 正是已冻结 U1 的「零风险」假 claim 重演 |
| C 全局 `default.json` | 加全局 `textureExcludeWords` | ❌ 否决 | 全局生效，其他书（如真用「凉」做质感基调的书）会失去保护，过宽 |

**关键判断**：「凉」是**裂日项目特有**的概念词（克制残频武器），不是 genre 属性。per-project 声明比"玄幻节点"更精准——别的玄幻书仍可正常检测「凉」。`threshold_overrides` 只喂源码树、够不着 CLI 树这个架构事实，决定了"节点级"在本项目里只能走 B（破隔离）或 A（换载体）——A 用 project.json 这个**本来就能到 CLI 树的载体**承接，是最小阻力解。

## 2. 改动清单（4 处，全在已验证通道上）

### 2.1 `检测工具/project-config.ts` — 接口补字段
`ProjectEntry` 接口（当前 :17-23）加一行：
```ts
/** per-work 质感词排除：如 裂日 的「凉」是核心概念词（克制残频武器），非均匀腔信号，CLI 树 texture_variety 检测时跳过。CLI 树不读 KB，故放 project.json 而非 KB 节点。 */
excludedTextureWords?: string[];
```
`readProjectConfig()`（:40-42）直接 `raw.projects ?? {}` 返回，**不白名单字段** → 运行时自动携带；仅 TypeScript 类型需补此声明。

### 2.2 `.inkweave/project.json` — 裂日 声明
```json
"裂日": {
  "name": "裂日",
  "path": "项目_裂日",
  "createdAt": "2026-08-15T00:00:00.000Z",
  "protagonistName": "林深",
  "excludedTextureWords": ["凉"]
}
```
其他项目不写此字段 → 默认全检测（零回归）。

### 2.3 `检测工具/check-chapter.ts` — 读取并透传
- :156（`const protagonistName = projEntry?.protagonistName;`）后加：
  ```ts
  const excludedTextureWords = projEntry?.excludedTextureWords;
  ```
- 4 处 `checkChapter` 调用（:177 / :210 / :216 / :225）补第 4 参：
  ```ts
  checkChapter(text, targetWords, protagonistName, excludedTextureWords)
  ```

### 2.4 `检测工具/checkers.ts` — 过滤词表（方案方核真身修正版）

> **⚠️ 致命漏改已补**：排除参数必须透传到 `checkChapter` 内部对 `checkTextureVariety` 的实际调用（**:1454**），否则 2.3 透传进来的参数到此断流、排除**永不生效**。原 2.4 只写了签名与 :390，漏了 :1454 这一内部调用点——按铁律补正。

改动点（共 4 处，均已在真身核对行号）：

- **(a) `checkTextureVariety` 签名（:377）**：`checkTextureVariety(text: string)` → `checkTextureVariety(text: string, excludedTextureWords?: string[])`，函数体开头加：
  ```ts
  // per-project 排除：如 裂日 的「凉」概念词，不参与均匀腔统计
  const activeWords = (excludedTextureWords && excludedTextureWords.length)
    ? TEXTURE_WORDS.filter(w => !excludedTextureWords.includes(w))
    : TEXTURE_WORDS;
  ```
- **(b) 匹配循环（:390）**：`for (const w of TEXTURE_WORDS)` → `for (const w of activeWords)`。**这是函数内唯一直接引用 `TEXTURE_WORDS` 的匹配点**，换它即可。
  - 说明（修正原误判）：原 2.4 写的「:397 也换」是错的——:397 是 `for (const arr of perSentence) for (const w of arr) freq[w] = (freq[w] || 0) + 1;`，它**并不引用 `TEXTURE_WORDS`**，遍历的是 :390 产出的 `perSentence`。:390 换 `activeWords` 后 `perSentence` 已不含「凉」，`freq` 自然只统计 active 词，:397 **无需动**。密集循环 / 单调霸权 / 报告取 top 词均基于 `perSentence`/`freq`，**全链路自动正确，不变**。
- **(c) `checkChapter` 内部调用（:1454）【原 2.4 漏改·必须补】**：`...checkTextureVariety(text),` → `...checkTextureVariety(text, excludedTextureWords),`。`checkChapter`（:1441）签名加 `excludedTextureWords?: string[]` 后，必须在此真正 **forward** 给检测函数，否则 2.3 透传进来的参数到这就断。
- **(d) 旁路 `checkChaptersAsync`（:1467，建议同路，非本轮回阻断）**：`checkChapter(ch.text, targetWords)` 目前连 `protagonistName` 都没透，属批量扫描独立入口。本 spec 范围（CLI 主路径 2.3 四处调用）不覆盖它；若后续有批量扫描需求应一并补 `excludedTextureWords`（及 `protagonistName`）。本轮回不做，记为已知缺口。

> 行号锚点（2026-08-29 核真身）：`checkTextureVariety` :377 / :390；`checkChapter` 定义 :1441、内部调用 :1454；`checkChaptersAsync` :1459 / 调用 :1467。`TEXTURE_WORDS` 常量 :375，仅 :390 一处用于匹配。

## 3. 预期效果（与既有数据对账）

- 当前 `texture_variety` 触发 **13 章**；其中 **7 章为「凉」驱动**（ch16/28/29/30/33/36/37，复核文档 §7 标定表已坐实）。
- 排除「凉」后：**6 章纯凉（ch16/28/30/33/36/37）归零**；**ch29 仍触发但已非凉**——它同时有密集「涩」（5 次），排除凉后由涩独立满足阈值，属正确行为（我们只想排除凉，不想排除涩）。

- **0 error 影响**：`texture_variety` 本来就是 warning 级；38–47 跑量批次若无「凉」滥用则完全不受影响。

## 5. 安全性 / 回滚

- per-project，默认 `undefined` → 行为等同现状（全检测），**零回归风险**。
- 仅影响 warning 级 `texture_variety`，不碰门禁 error。
- 回滚 = 从 `project.json` 删该行，**无需改代码**。

## 6. 非目标（防方案蔓延）

- ❌ 不建"通用节点级排除机制"（B 已否，重演 U1 破隔离）
- ❌ 不碰 `TEXTURE_WORDS` 常量本身（「凉」留作其他书的有效信号）
- ❌ 不扩展到其他词（仅「凉」pilot；其他词按各自实测数据另议）
- ❌ 不动 KB / `mergeConfig` / 源码生成树
