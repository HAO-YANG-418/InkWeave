# R3 接线方案：把 checker error 接进 reflection 自纠循环

> 配套：v2 执行清单 §3#0（前置步）。本文件把"接线"写成可直接落地的精确指令。
> 状态：**R2 已 100% 闭环**（代码方 apply A 两处正则 + 验证 PASS，已实核）。本方案待代码方落地。

## 0. 问题（已实地核实，非推测）

| 事实 | 位置 | 证据 |
|------|------|------|
| reflection 的 `passed` 是**纯分数制**，不读 checker error | `reflection/engine.ts:459 / 593` | `passed = overallScore >= qualityGate` |
| reflection 的 concern 全是数值 severity（0.2/0.3…），grep 证明**从不引用** `checker`/`violation` | `reflection/engine.ts` | 全文无 `checker`/`hasErrors` 引用 |
| orchestrator 的"生成→反思→重写"循环**只调 `reflectAsync`，从不调 checker** | `writing/orchestrator.ts` | grep 确认零 `check/checker/violation` 引用 |
| gwe-engine 跑了 `this.check()`，但只 `emit('ai:done')` + 挂返回值，**不进任何循环** | `gwe-engine.ts:416-422` | 无循环消费 `checkResult` |

⇒ **结论**：`checker.passed = !hasErrors` 和重写循环用的 `reflection.passed` 是**两套互不相连的 gate**。R3「升 checker error 逼自纠」当前是断的——升 error 只让 `checker.passed=false`，重写循环根本不读它。本方案补"接线"。

## 1. 设计原则

1. **注入点**：把 checker 的 `error` 级 violation 转成一条合成 `QualityConcern`（`dimension: 'rule_check'`），注入 reflection 的 `concerns`，并**强制** `passed = overallScore>=qualityGate && !hasCheckerError`。
2. **触发点**：orchestrator 在生成循环的每一轮（首生成 + 钩子重写 + 维度重写 + 兜底重写）调一次 checker，把 `violations` 传给 `reflectAsync` 的第 3 参数。
3. **定向重写**：合成 concern 进 `generateRewriteInstructions`（severity 0.9 > 0.3 过滤线）→ 兜底整体重写的指令里包含 checker 违规 → **重写是定向修 checker 报的问题**，不是盲目重写。
4. **不死循环**：受 `maxRewriteRounds` 上限兜底（orchestrator:540 / 575）。
5. **双路覆盖**：注入在 `reflect()` 内做，且 `reflectAsync()` 的混合分支（552-600）也单独做——因为 `reflectAsync` 无 LLM 时早返回 `ruleResult`（556），混合路径还自己重算 passed（593），两路都得注入，否则漏一路。

**(b) `reflect()` 方法（453-477 行）重写 concern 注入**
> 真实代码：453 行 `reflect(input, round=0)`，454 行 `const concerns = this.evaluateAllDimensions(input)`（**未过滤的原始 concern 数组**），459 行 `passed = overallScore >= qualityGate`，461-469 行 result 里才 `concerns.filter(c=>c.severity>0.3)`。下方改动保持真实变量名 `concerns`，注入合成 concern 到 `concerns` 后再算 passed。
```ts
reflect(input: ReflectionInput, round = 0, checkerViolations?: RuleViolation[]): ReflectionResult {
  const concerns = this.evaluateAllDimensions(input)
  // —— R3 接线：把 checker error 转成合成 concern（并入 concerns，后续 result 里统一过滤）——
  let hasCheckerError = false
  if (checkerViolations && checkerViolations.length) {
    const errs = checkerViolations.filter(v => v.severity === 'error')
    if (errs.length) {
      hasCheckerError = true
      concerns.push(...errs.map(v => ({
        dimension: 'rule_check' as QualityDimension,
        severity: 0.9,
        description: `[检测期违规 ${v.ruleId}] ${v.message}`,
        suggestion: v.suggestion ?? '按检测建议修正',
        location: undefined,
      })))
    }
  }
  const dimensionScores = this.calculateDimensionScores(concerns)
  const overallScore = this.calculateOverallScore(dimensionScores)
  const highlights = this.extractHighlights(input, concerns)
  const passed = overallScore >= this.config.qualityGate && !hasCheckerError

  const result: ReflectionResult = {
    overallScore,
    passed,
    dimensionScores,
    concerns: concerns.filter(c => c.severity > 0.3).sort((a, b) => b.severity - a.severity),
    highlights,
    summary: this.buildSummary(overallScore, passed, concerns),
    round,
  }
  if (!passed) {
    result.rewriteInstructions = this.generateRewriteInstructions(concerns, input)
  }
  return result
}
```

## 4. 风险与边界（已识别）

- **反射分数不降也不影响**：因 `passed` 被显式 `&& !hasCheckerError` 强制，不依赖 `DIMENSION_WEIGHTS` 的权重数学，鲁棒。
- **`findWeakestDimensions` 可能不选 `rule_check`**：专项重写（钩子/维度）不感知 checker，但**兜底整体重写（575）靠 `rewriteInstructions` 定向修**，覆盖。后续可让 `findWeakestDimensions` 也纳入 `rule_check`。
- **checker 抛错不影响生成**：`runChecker` try/catch 返回 `[]`，检测器崩了也不阻断写作。
- **与 R4 关系**：R4（给 `源码/checks/` 补字数检查、挂 `MergedConfig.wordCount`）落完后，字数不足会自动产生 `word_count_short` error → 经本接线触发重写 → **"写空"在生成阶段被真拦**（治本），不再只靠 CLI 事后报。
