# 编译集工程债 P3 · 补齐缺失模块（2026-09-01）

> 用户"碰吧"授权推进 P3。本文记录核真身过程、修复清单、验证结果与边界声明。

## 1. 问题根因

`源码/writing/orchestrator.ts` 加进 `tsconfig` include 时 `TSC_EXIT=2`，根因是其传递依赖 `writing/engine.ts` 指向**一批从未实现的模块** + `kb-loader.ts` 缺 `preset_miner.json`。这些模块不是"漏加一个文件"，而是**整体未落地**。

## 2. 核真身（不凭记忆，实查）

- `源码/technique/`、`源码/anti-pattern/` 两目录**整体不存在**（非单个文件缺失）。
- `源码/kb/presets/` 有 16 个 `preset_*.json`，但**无 `preset_miner.json`**（kb-loader:176 动态 import 它）。
- `writing/engine.ts` / `writing/orchestrator.ts` 是**活跃运行时代码**：被 `writing/agent.ts`、`writing/index.ts`、`intent/index.ts`、`reflection/index.ts` import，**不是死代码** → 必须纳入编译集被类型检查。
- `planning/pacing-curve.ts` 等依赖**存在**，非缺失项。
- `tsconfig` 当时**未设 `noEmitOnError`** → 解释了历史上"缺模块仍 emit"的隐患（03:23 那次 EXIT=2 仍 emit）。

## 5. 连带根治

`tsconfig.json` 加 `"noEmitOnError": true` → build 任何 TS 错误即阻断 emit，**根治"失败也 emit、静默不同步"隐患**（铁律①记载的根因）。
