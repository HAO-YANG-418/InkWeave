## 一、发现：文档改了，运行时没改

上一轮我把 `知识库/预设/通用网文基础.md` 的默认预设改成「口语白话 + 内外结合 + 长短交错」，记为「默认预设去冷峻 ✅」。

**核真身后：这个改动对运行时无效。**

| 事实 | 证据 |
|---|---|
| `知识库/预设/*.md` **不是运行时数据源** | 全树 grep 仅 `检测工具/pre-analysis.ts:112` 命中，且只是拼诊断路径字符串给人看 |
| `preset_base_webnovel.json`（通用网文基础真身）**是死文件** | `源码/kb-loader.ts:165-182` 的 `loadAllPresets()` 只加载 12 个题材预设，无 base_webnovel |
| 运行时默认底座 = **硬编码** | `源码/node-registry.ts:449 getDefaultSelectionsFull()` → 逐个取 `node.defaultOptionId` |
| 注入路径确实存在 | `源码/prompt-builder.ts:293-306`：`【${node.name}】\n${kb.system_prompt}` 进 system prompt 第 [2] 层 |

**即：改 .md 文档 ≠ 改引擎行为。上一轮的「去冷峻」只落在纸上。**

## 二、运行时默认底座实况（修复前）

| 节点 | 运行时默认 | .md 文档写的 | 是否漂移 |
|---|---|---|---|
| 语调 `node_tone` | **`opt_tone_serious`（严肃正剧）** | 口语白话 | ❌ **冷峻种子在正中间** |
| 情感 `node_emotion_style` | **`opt_emotion_show`（option_name 就叫「克制留白」）** | 内外结合 | ❌ **冰山理论种子在** |
| 节奏 `node_sentence_rhythm` | `opt_rhythm_medium` | 长短交错 | ⚠️ 不一致 |
| 描写 `node_description_style` | `opt_desc_sensory`（感官沉浸） | 感官沉浸 | ✅ 一致 |
| 锚点 `node_anchor_density` | `opt_anchor_standard` | 标准 | ✅ 一致 |

### 两处冷峻种子的原文（决定性证据）

`opt_tone_serious` constraints：
> 「**禁止网络用语、口语碎片、戏谑调侃语气**，保持叙事庄重感」
> 「情感表达克制，禁止角色大喊大叫」
> 「句子偏长，结构完整」

→ **这是 A11 人味·自嘲缺失的直接种子**（v3 全章零调侃）。

`opt_emotion_show` system_prompt 首句：
> 「克制留白的核心是'冰山理论'——**写出来的只有八分之一，剩下八分之七在水面下**。你永远不直接告诉读者角色在想什么……」

→ **这是「留白＝藏逻辑」的运行时真身**。

### 两条代码自相矛盾的铁证

- `opt_tone_colloquial` 的 system_prompt 自称「**口语白话是默认叙事基调**」，但 registry 默认却是 serious
- `opt_emotion_both` 的 option_name 自称「内外结合**（推荐默认）**」，但 registry 默认却是 show

## 三、修复（已落）

### 1. 改运行时默认底座 —— `源码/node-registry.ts`

| 节点 | 行 | 改前 → 改后 |
|---|---|---|
| `node_sentence_rhythm` | :28 | `opt_rhythm_medium` → **`opt_rhythm_mixed`** |
| `node_emotion_style` | :97 | `opt_emotion_show` → **`opt_emotion_both`** |
| `node_tone` | :110 | `opt_tone_serious` → **`opt_tone_colloquial`** |

同步修正 options 数组里的「默认」注释，避免旧注释继续误导。

**现在文档与运行时完全一致**（长短交错 / 内外结合 / 口语白话 / 感官沉浸 / 标准锚点）。

### 2. 给仍可能被手动选中的冷峻节点补「好懂红线」注脚

默认改了，但用户手动选 serious / cold / show 时仍会复发 → 三个节点的 `system_prompt` 顶部加注脚：

| 文件 | 注脚要点 |
|---|---|
| `node_tone/opt_tone_serious.kb.json` | 「禁止戏谑调侃」**仅约束叙事者腔调**，不约束角色说话——角色自嘲、贫嘴、带刺玩笑是人味来源 |
| `node_tone/opt_tone_cold.kb.json` | 冷峻是**叙事腔调**选择，不等于把事情写含糊；冷腔调+不说清＝读者弃书 |
| `node_emotion_style/opt_emotion_show.kb.json` | 冰山理论**只停情绪层**；事件因果、动作链、设定逻辑**不许藏** |

统一红线：克制≠难懂，留白≠藏逻辑；含蓄/克制/留白只适用情绪层，绝不适用信息层。

**编译链路说明**（澄清一条容易误判的机制）：`node-registry.ts` 不在 `tsconfig.json` 的 `include` 名单里，但它被 `源码/prompt-builder.ts:14` import，因此被**传递编译**进 dist。本次 dist 同步是靠这条链，不是靠 include 名单。
> ⚠️ 风险：这条链依赖 prompt-builder 的 import 存在。若将来重构移除该 import，node-registry 会静默退出编译集。建议显式加入 include（代码方活）。

## 五、上一轮诊断的错误（认）

上一轮我判定：**「A7 五感 / A6 身体锚点是罚则没成底座，需下沉」——结论错误。**

核真身后：这两项的种子**本来就在运行时默认底座里**，而且写得相当具体：

| 种子来源 | 原文 |
|---|---|
| `opt_dialogue_natural` constraints | 「**连续对话不超过4句必须穿插动作/神态/环境描写**」「每3-4句对话之间必须插入一个动作或微表情」 |
| `opt_anchor_standard` constraints | 「**对话段落也要有适当的锚点穿插（动作标签）**」 |
| `opt_emotion_show` constraints | 「每250字至少有1处身体锚点」「每处重要场景至少调用**两种感官**，触觉与嗅觉最易被忽略」 |
| `opt_desc_sensory` system_prompt | 完整五感教学（视觉40-45% / 听觉20% / 嗅觉15% / 触觉20%）+ 8 条 constraints |

**v4 五感退化的真因**：我盲写时**没有加载任何 KB 种子**（agent 系统提示不注入引擎 KB），所以 v2/v3/v4 验证的是「agent 自身写作倾向」，不是「skill 底座效果」。当时默认还是 serious+show，我更没读它们。

**方法论修正**：模型层盲写必须**先手动加载运行时默认底座的 system_prompt**（模拟引擎 [2] 层注入），否则测的是假象。
