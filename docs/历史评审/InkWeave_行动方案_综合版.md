# InkWeave 改进行动方案 · 诸葛亮综合版（供 trea 执行）

> 背景：原评价（交叉评审版）已获两个 agent 独立确认，8 条结论全部认同、有证据支撑。本文件综合两 agent 意见，修正执行顺序与验收标准，供指定修复 agent（trea）直接执行。
> 重要前提：原评价 agent 不参与修改，本方案由 trea 落地。

---

## 0. 对 trea 原方案的 3 处修正（必读）

1. **"0 error" ≠ 质量好**：fingerprint 的 errors 为空只说明硬规则（破折号/确定性违规）未触发；风格单调恰恰是未被 error 捕获的部分。"0 error"与"文风 demo 级"不矛盾，反而印证检测盲区。验收时不许用"0 error"证明质量。
2. **#1 风格约束 必须依赖 #2 反向闭环 才生效**：先建闭环管道，再把风格上限作为"第一条通过闭环注入的硬约束"。若先加规则后建闭环，会复刻 4.3"感官节点未生效"的失败。二者合并为同一波次。
3. **业务排序**：目标是卖给非技术人群（抖音电商方向）。#3 轻量模式 + #4 打包 skill 是营收解锁键，不得排最后，应与 craft 波并行推进。

---

## 1. 执行波次

### Wave 1 — 质量闭环（最高杠杆，先打）
目标：治最严重问题（风格单一），并建立"检测→生成"通用机制（一次建设、长期受益）。

- **Step A：反向闭环（#2，先做 plumbing）**
  - 扩展 fingerprint / 写后检查流程：每章检测后，取 `warnings` 中出现频率最高的 2–3 类，自动写入下一章「生成指令.md」的"本章禁忌"区（新增固定段落）。
  - 写前分析（pre-analysis）读取该区并强制纳入生成约束。
  - 验收证据：下一章 fingerprint 中，被注入的 warning 类数量应下降；且「生成指令.md」确实含"本章禁忌"段落。
- **Step B：风格硬约束（#1，作为闭环首条规则）**
  - 在"本章禁忌"机制上挂第一条规则：单章"穿过X/往X里流/不是X是Y"类堆叠句式 ≤ N 次（建议 N 先设 8，按章节类型可调）；连续递进句占比封顶。
  - 验收证据：用第14章同款上下文重跑，此类句式显著下降。

### Wave 2 — 可交付 / 营收解锁（与 Wave 1 并行或紧随）
- **#3 轻量模式**：新增"快写模式"分支——跳过逐段推演、只跑关键门禁（冷却/红牌），降低非硬核用户门槛。
- **#4 打包成可装 skill / 网页壳**：把 `npx tsx` 调用隐藏进壳（WorkBuddy skill 包 或 本地网页/CLI 包装），让非技术用户无需 Node 环境即可用。这是"卖课变现"的交付前置。

### Wave 3 — 收尾
- 统一模块版本号（主/写作/大纲/设定 同步到同一版本）。
- 补效果度量：抓 10 章盲评（修复前 vs 修复后）对比 baseline，产出可对外讲的"完读/追读提升 X%"数据。

---

## 2. 给 trea 的硬约束（防复发）

- 任何"新增约束"都必须走闭环（写入生成指令并被 pre-analysis 读取），禁止只加在文档里。
- 修完后必须做回归：用 `项目_裂日` 现有章节同上下文重跑，给出"修复前 vs 修复后"的句式计数对比，不允许只说"已优化"。
- 不擅自引入新大版本号震荡；如需改版本，四模块同步。

---

## 3. 验收清单（trea 完工须逐项自证）

- [ ] 反向闭环存在：下一章「生成指令.md」含"本章禁忌"，且来自上一章 warning。
- [ ] 风格约束生效：重跑样本章，"穿过/往…流"类句式下降 ≥ 50%。
- [ ] 感官均衡：样本章视觉占比降至 < 60%，其他感官有体现。
- [ ] 轻量模式可走通：非技术路径能产出章节，不依赖手动 npx tsx。
- [ ] 打包形态：存在可装 skill 包或网页壳，目标用户能直接用。
- [ ] 版本号四模块统一。
- [ ] 效果度量：≥10 章盲评对比数据。
