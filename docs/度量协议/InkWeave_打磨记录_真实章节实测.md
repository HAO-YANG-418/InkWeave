## 一、实测方法

- 用项目_裂日 15 个正式章节（排除 `_v4.8`/`_r2` 等历史迭代和 fingerprint 文件）逐个跑 `check-chapter`。
- **关键坑**：CLI 入口 `inkweave.mjs` 跑的是 `dist/*.js`（编译版），改 `检测工具/*.ts` 源码必须 `npx tsc` 重编才生效。Git Bash 处理中文+空格文件名 + emoji 正则会出 artifact（误报"禁用字/字数严重不足"），改用 python 调 node + python 解析 stdout 才可靠。

## 二、发现的三类问题 + 修复

### 问题1：排比堆叠误杀"在/从/往"（严重）
- **现象**：第11章被标"排比堆叠 84 处：在×5、在×11、从×3"→ error。
- **根因**：`checkStyleStacking` 的 `stackingVerbs` 把单字介词 `'在'/'从'/'往'` 列进去，模式 `(在)[^，]{1,30}[，]` 匹配所有"在他身体里，""从桌上，"等正常方位短语，海量误杀。
- **修复**：`stackingVerbs` 移除 `'在'/'从'/'往'`，只留真动词（穿过/听见/看见/闻到/感到/触到/沿着/顺着）。

### 问题2：跨章重复连带误杀"在"
- **现象**：第14章跨章标记"在×23"要求替换（对话白名单没拦住方位介词）。
- **根因**：跨章复用上章 fingerprint 的 `verbStackingVerbs`，若含"在"则误杀；且功能词高频必现。
- **修复**：`checkCrossChapterRepeat` 加高频功能词白名单（在/从/往/是/有/他/我/你/就/都/还/又/把/被/让/给/向/对/和/与/着/了/的/而/却/也/便），即使上章残留也跳过。

### 问题3：感官密度 error 门禁过严（用户决策）
- **现象**：铁则八"视觉≤45% / 触觉≥视觉"作为 error 门禁，15 章 14 章因"视觉>45%"判 error → 废章。
- **判断**：视觉是人类主导感官，天然占优，此阈值作为硬门禁几乎必然每章不及格，作者会弃用。
- **用户决策**：**降级为 warning**（保持铁则八"鼓励多感官"指导意图，但不废章）。
- **修复**：
  - `checkSenseDensity`：`sense_density_balance` 从 `error` 降 `warning`，并改掉"为error阻断生成"的误导措辞。
  - `checkSenseDensityWithPrev`：删除"升级为 error"逻辑，仅保留"上章复发提醒"消息（不改 severity，避免连续章节连环废章）。
- 同步按章节号有序重生成全部 fingerprint（闭环数据用修正引擎，旧的感官 error 标记清除）。

### 澄清（非 bug）："禁用字/字数严重不足"是假警报
- Grep 证实裂日章节**无破折号**、字数 2600–3500 逼近目标，真实不存在此 error。是 Git Bash 中文文件名 + emoji 正则的脚本 artifact，已改用可靠扫描方式。
