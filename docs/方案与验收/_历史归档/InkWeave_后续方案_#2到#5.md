## #2 反向闭环升级为「生成端硬约束」

### 目标
把"上一章指纹 → 本章禁忌"从**纯文字软提示**升级为**带反例 + 正例模板 + 跨章重复校验**的硬信号，并补上感官维度。让 LLM 不只是"别这样"，而是"该那样"，闭环真正降低堆叠/失衡复发率。

### 现状（已核实）
- `检测工具/pre-analysis.ts:428-529` `injectFingerprint` 只输出 verbStacking/nameStacking/deDensity 的"禁止"文字，且**无 sense_density**。
- 检测器未做"跨章重复句式"校验——同一堆叠句式在相邻章反复出现检测不出。

### 具体改动
1. **pre-analysis.ts `injectFingerprint` 重构**：
   - 对每类 stylePattern，**附上章具体句式样本作为反例**（如 verbStacking 提取出"穿过X穿过Y穿过Z"原句）。
   - **新增正例模板**：给出本章替代写法（例："上章用'穿过'堆叠，本章改用分镜式：先写动作落点，再写环境回应，最后给一次感官收束"）。
   - **补 sense_density 进禁忌**：上章视觉>45% 则本章强制"非视觉感官≥1处/场景"。
   - **合并 step0 配方与禁忌**：现在 step0（风格配方）和 injectFingerprint（禁忌）是两段独立输出，LLM 可能只看一段。把"本章该用听觉主导 + 上章排比禁忌"合并成一段"本章风格契约"，避免信号分裂。
2. **checkers.ts 新增 `crossChapterRepeat`（warning 级）**：读上章 fingerprint 的 verbStacking 具体句式，若本章出现**同构句式**（如仍含"穿过X穿过Y穿过Z"模式）则报 warning。把"事后惩罚"前移到"复发即标"。
3. **检测器把 sense_density 闭环**：上章 error 的感官维度，本章若仍超阈值，severity 升一级（warning→error）。

### 验收标准（必须实测）
- 跑 `pre-analysis 16` → 输出含"上章具体堆叠原句(反例) + 正例模板 + 上章感官失衡→本章强制非视觉"。
- 造一个"复刻上章堆叠"的测试短文 → 检测器 `crossChapterRepeat` 报 warning，退出码随严重度变化。
- 验证 step0 与禁忌合并后输出为单段"风格契约"，无信号分裂。

### 风险
- 反例/正例模板过长会撑爆 prompt，需控制每类 ≤2 例。
- 跨章重复校验可能误伤刻意呼应（如前传伏笔），建议只对"连续2章同构"判定。

## #3 轻量模式验证 + 接知识库配方

### 目标
让非技术用户可用的"快写模式"真正产出合规文风（而非跳过约束反而更易堆叠），并验证不崩。

### 现状（已核实）
- `检测工具/quick-write.ts` 存在，但**门禁3只接了 verbStacking/dashes/notXButY，完全没接 step0 风格配方**（预设/多样性轮换）。等于轻量模式放弃了知识库工程化 v1 的核心收益。
- 从没实测跑过（无运行记录）。
- 命令行仍是 `npx tsx`（与打包形态不一致）。

### 具体改动
1. **quick-write.ts 接入 step0 风格配方**：在"关键门禁"前增加"本章风格配方"段（主导非视觉感官 / 修辞变奏 / 镜头侧重，取自 step0 同款计算），让轻量模式也享受多样性轮换。
2. **实测跑 3 章**（如 16/17/18）：确认 (a) 不崩、(b) 简报含风格配方、(c) 写完检测能过门禁或报明确 error。
3. **命令行对齐**：`npx tsx 检测工具/quick-write.ts` → `inkweave quick`，与 #4 打包一致。

### 验收标准
- 跑 `inkweave quick 16 3000 --project 裂日` 正常输出且含"风格配方"段。
- 3 章全部跑通，至少 2 章过门禁或产出明确可改 error。
- 轻量模式产出的文风多样性指标 ≥ 标准模式的 80%（用 sense_density 分布验证）。

### 风险
- 轻量模式精简了门禁，可能漏掉 preset 硬约束（触觉≥视觉），需确认 step0 配方已含该约束。

## #4 打包成浏览器模块（进 Storyvein）

### 目标
把 InkWeave 的检测器 + 预设加载 + 风格配方**编译成纯浏览器 TS 模块**，挂进你半成品软件 Storyvein，让它写时实时质检 + 出配方。这才是"对接半成品软件"的真形态。

### 现状（已核实）
- trea 的 `inkweave-web.js` 是 **Node 服务（spawn+fs）**——Storyvein 是纯浏览器 React（CodeMirror + Dexie），**跑不了 fs/子进程**，该壳进不去。方向错。
- Storyvein `src/engine/gwe/` 已内嵌完整质检引擎：`checker.ts`、`checks/`、`kb/`（知识库）、`node-registry.ts`（节点注册）、`prompt-builder.ts`、`gwe-engine.ts`。说明"浏览器内质检"这条路趟过，可直接对齐结构。

### 具体改动
1. **拆出纯函数核心**：把 `checkers.ts` 的 `checkChapter(text, stats, options)` 改成**不依赖 fs**——输入是字符串 + 选项对象（预设名/目标字数），输出 violations。知识库/预设读取改为接收已加载的 JSON/字符串参数（由调用方从 Storyvein 的 Dexie 或打包进 bundle 的 JSON 提供）。
2. **新建 `src/engine/inkweave/`**（或并入 gwe）：`checker.ts`(浏览器版)、`preset-loader.ts`(读打包进 bundle 的预设 JSON)、`style-recipe.ts`(step0 配方计算，纯函数)、`index.ts`。
3. **接 `writingEngineBridge.ts`**：写时（onChange 防抖 800ms）跑 checker → 侧栏出实时报告 + 风格配方提示卡；保存时写 fingerprint 进 Dexie。
4. **预设/知识库打包**：把 `知识库/预设/*.md` + `节点/*/选项.md` 在构建期编译成 JSON 随 bundle 发布（参考 gwe 的 `kb/` 做法）。

### 验收标准
- `src/engine/inkweave/checker.ts` 在浏览器环境（无 Node）`import` 后能对一段字符串跑检测，返回与 CLI 版一致的 violations。
- Storyvein 编辑器输入一段含排比堆叠/视觉>45% 的文本 → 侧栏实时标红 + 出"本章风格配方"卡。
- 预设 `都市异能-番茄V3.1追读版` 在 Storyvein 内加载成功，触觉≥视觉约束生效。

### 风险
- 中文检测正则/wc 计算在浏览器需自实现（不能用 Node `fs` 读文件计字数）。
- bundle 体积：22节点×多选项 md 编译成 JSON 可能较大，需做按需加载。

## #5 效果度量（卖课弹药）

### 目标
用"修复前 vs 修复后"盲评，量化"文风多样性/可读性提升"，给卖课攒硬证据。这是变现硬伤，几轮都没碰。

### 具体方案
1. **选 5 个固定章节提纲**（高潮/过渡/日常/战斗/揭秘各一）。
2. **两个版本生成**：
   - A 版（旧）：用 v4.5.3 逻辑（旧检测盲区 + 无知识库配方）生成。
   - B 版（新）：用 v4.8（新门禁 + step0 配方 + 反向闭环）生成。
3. **盲评设计**：找 10 个读者 / 其他 agent，打乱 A/B 顺序，按 4 维度打分（多样性 / 可读性 / 疲劳度 / 雷同感），1-5 分。
4. **出对比数据**：B 版在"多样性/疲劳度"上均值提升 X%；附统计显著性（哪怕只是均值差）。

### 验收标准
- 交付 `InkWeave_效果度量报告.md`：含 5 章 A/B 全文 + 10 份评分表 + 均值对比图。
- 明确结论："使用 v4.8 后，读者疲劳度评分从 X 降至 Y（-Z%），雷同感从…"。

### 风险
- 样本小（10人）只能算"趋势证据"，不能算统计显著；卖课时措辞要诚实。
- LLM 生成本身有随机性，A/B 需各固定 seed 或多次取中位数。
