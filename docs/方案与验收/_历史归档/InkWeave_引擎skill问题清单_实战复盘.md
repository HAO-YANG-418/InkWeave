## 二、逐项详述（含复现 + 改法建议）

### D1 ｜ 感官基线契约自相矛盾（🔴 高）

**现象**
- `pre-analysis.ts` 第122-123行：`dominantSense = allSenses[chapterNum % 5]`，契约文本明确写"该感官可主导分布（占比可>45%）"（第135、141行）。
- 但 `checkers.ts` 第530-538行 `sense_tactile_below_visual`：**无条件**要求 `触觉 ≥ 视觉`，一旦 `visualVal > tactileVal` 即报 warning。
- 二者直接冲突：视觉/听觉/嗅觉/味觉基调章，视觉天然最高，永远满足不了"触觉≥视觉"。

**实战证据（fingerprint 交叉表）**

| 章 | 基调感官 | tactile<visual 触发？ | sense_density_balance 触发？ |
|----|---------|----------------------|------------------------------|
| 17 | 视觉 | 否 | 否 |
| 18 | 听觉 | **是** | 否 |
| 19 | 触觉 | **是** | 否 |
| 20 | 嗅觉 | **是** | 是 |
| 21 | 味觉 | **是** | 是 |
| 22 | 视觉 | **是** | 否 |
| 23 | 听觉 | **是** | 是 |
| 24 | 触觉 | **是** | 否 |
| 25 | 嗅觉 | **是** | 是 |

- 8/9 章触发 `tactile<visual`（唯一未触发是 ch17，但 ch22 同为视觉基调却触发 → **同基调不同结果，行为不一致**）。
- **最荒诞**：ch19、ch24 是"触觉基调章"，本应触觉主导，仍被报"触觉<视觉"——说明该约束在视觉自然偏高时数学上几乎不可满足。

**根因**：检测器层不知道"本章基调感官"是什么，用了全局硬约束覆盖轮换逻辑。

**改法建议（给代码方）**
1. `checkSenseDensity` 应接收 `pre-analysis` 算出的 `dominantSense` 参数。
2. 仅当 `dominantSense === '触觉'` 时，才启用 `触觉 ≥ 视觉` 硬约束；其余基调章改为"非基调感官每场景≥1处点缀"的软校验（即沿用 sense_density_balance 的 warning 语义，去掉 tactile<visual 这条）。
3. 或彻底废弃 `sense_tactile_below_visual` 规则，统一由 `sense_density_balance` 表达"防单一霸权"，避免双规则打架。

### D2 ｜ `不是X是Y` 检测器 severity 与铁则十二不符（🔴 高）

**现象**
- 生成契约（铁则十二）措辞为"**零容忍 / 硬禁 error 级**"。
- 但 `checkers.ts` 第722行：`severity = allMatches.length >= 5 ? 'error' : allMatches.length >= 3 ? 'warning' : 'info'`。
- 即：1–2 处只报 `info`，3–4 处报 `warning`，**5 处以上才是 error**。

**实战证据**
- 9 章共 8 章出现 `not_shi_pattern`，最高单章 3 处（ch19/21/23），全部止步于 info/warning，**从未触发 error**。
- 含义：作者写 4 处"不是X是Y"仍可通过门禁，与"硬禁"承诺严重不符。

**改法建议**
- 二选一：
  - **(A) 对齐契约**：将阈值改为 `>=1 即 error`（硬禁），并在 `pre-analysis` 契约里把"零容忍"落到实处；
  - **(B) 修改契约**：若认为 1 处即废章过严，则把铁则十二"硬禁"措辞改为"≤2处 warning，≥3处 error"，并同步改检测器为 `>=3 error`。
- 当前状态是"契约说硬禁、检测器放水"，两边必须统一，不能留缺口。

---

### D3 ｜ 碎句检测器误杀网文刻意短句（🟡 中）

**现象**
- `checkers.ts` 第733-742行：任意连续 3 句 ≤8 字即报 `short_sentence_fragment`（warning）。
- 不区分叙事功能：番茄风都市异能在**危险/发现/选择/打断**场景刻意用短促句制造节奏（如"他闭了闭眼。把这念头按下去。现在顾不上心软。"），属正当技法。

**实战证据**
- 9 章共触发 **28 次**，是出现频率最高的警告，几乎章章有。
- 但碎句在紧张场景是风格选择，非瑕疵。

**改法建议**
1. 增加"功能白名单"：若连续短句出现在**对话段**或含动作/感官动词（走跑看说拿等 + 冷热敷刺等），降为 info 或不报。
2. 或把阈值从"连续3句≤8字"收紧为"连续4句≤6字"，只拦真正碎成渣的句子。
3. 在 `pre-analysis` 契约里明确："短句仅保留在危险/发现/选择/打断位"——这恰说明检测器应识别这些位置并放行。

### D4 ｜ 字数门禁阈值失真（🟡 中）

**现象**
- `checkers.ts` 第1122-1125行：`ratio < 0.7`（即 <2100 字）才报 error；`0.7–0.85`（2100–2550）报 warning。
- 生成契约目标写的是"目标字数3000"（pre-analysis 头部 + 节点表）。

**实战证据**
- 9 章字数：2129 / 2140 / 2151 / 2162 / 2223 / 2252 / 2545 / 2676 / 2729。
- **7/9 章低于 3000**，最低 ch20 仅 2129（完成率71%），却以 0 error 过门禁。
- 后果：实战中"通过门禁"不等于"达到契约目标字数"，质量基线被悄悄拉低。

**改法建议**
1. 统一口径：error 阈值改为 `< 0.9`（<2700），warning 改为 `0.9–1.0`（2700–3000），与契约"目标3000、±10%容差"对齐。
2. 或在 `pre-analysis` 里明示"±10% 容差"，让检测器与契约用同一数字，消除歧义。

---

### D5 ｜ 两条感官规则逻辑重叠（🟡 中）

**现象**
- `sense_density_balance`（视觉>45% 报 warning）与 `sense_tactile_below_visual`（触觉<视觉 报 warning）指向同一件事（视觉霸权），却分两条规则。
- 实战中有的章两条都触发（ch20/21/23/25），有的只触发一条（ch18/19/22/24），输出冗余且让读者难判断主次。

**改法建议**
- 合并为单条 `sense_balance`：当 `视觉占比>45% 且 非视觉感官无每场景点缀` 时报一次 warning，消息同时说明"视觉偏高+需补非视觉"，删掉 `sense_tactile_below_visual` 独立规则（与 D1 改法合并）。

---

### D6 ｜ 破折号额度与铁则十二措辞矛盾（🟢 低）

**现象**
- `checkers.ts` 第320-332行：破折号允许 ≤2 处作为"节奏破格"，超出才 warning。
- 注释称"这是对铁则十二'零容忍'的人性化修正"——但铁则十二正文仍写"零容忍/硬禁"，未同步更新。

**改法建议**
- 在铁则十二正文里补一句："破折号每章≤2处作节奏破格，超出改逗号"；或把 `forbidden_char_dash` 说明与契约措辞对齐，避免"零容忍"字面误导。

## 三、优先级与交付建议

1. **必须先修 D1、D2**：这是契约层硬矛盾，导致每章必出"该报错的不报 / 不该报的硬报"，污染所有实战数据，也让作者无所适从。
2. **次修 D3、D4**：误杀 + 阈值失真，影响产出质量基线，但不阻塞门禁。
3. **顺手合并 D5、对齐 D6**：清理冗余与措辞。
4. 修复后，建议对第17–25章**全量重跑 `check-all`** 做回归，确认 warning 总数显著下降、且 error 依旧 0（门禁未被破坏）。
