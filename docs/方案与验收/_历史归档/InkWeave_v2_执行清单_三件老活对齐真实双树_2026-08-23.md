## 0. 架构事实（已实地核对，v2 的全部前提）

**两套检测器树并存，职责不同：**

| 维度 | `源码/checks/`（经 `源码/checker.ts` 汇总） | `检测工具/checkers.ts` |
|------|------|------|
| 角色 | **生成时检测器（被 `gwe-engine.ts:418` 调用）**：但其 `passed=!hasErrors` **未接入** reflection/orchestrator 重写循环——后者只用 `reflection.passed`（分数制，见下方⚠️修正）。checker 的 error 输出在生成链路是**死胡同**，仅 CLI 离线报告消费。 | CLI 离线验收树：`inkweave.mjs → dist/检测工具/check-chapter.js` → `检测工具/check-chapter.ts` 调用 |
| 检测器数量 | **26 项注册总数**：13 个独立文件在 `源码/checks/`（V3.2 泛用，无去 AI 味项）；去 AI 味项（cliche_reaction / fake_reactions / fake_hook / cliché_phrases / simile_density / sensory_balance / info_density 等）**全部内联在 `源码/checker.ts`**（不在 `源码/checks/`） | D1–D6 迭代，偏基础正则/统计 |
| D2 口径 | `>2?warning:info`（第24行，**无 error 级，最松**） | `>=3?error`（方案 B，已落地） |
| 字数检查 | **无**（grep 全文确认） | **有**（D4 `<2700=error`） |
| 你实际验收用的 | 否（引擎内部） | 是（`inkweave check` 第17–26章回归） |

**关键机制（已核实，R3 治本依据——⚠️ 2026-08-23 实测修正）：**
- `源码/checker.ts:257/264`：`hasErrors = violations.some(v => v.severity==='error')` → `passed: !hasErrors`（error 级 gate，独立存在）。
- `reflection/engine.ts`：`passed = overallScore >= qualityGate`，overallScore 来自它**自己从文本算的 concern 维度**（severity 全是数值 0.2/0.3/0.4…，grep 证明它**从不引用 `checker`/`violation` 的 error 输出**）。
- `writing/orchestrator.ts`：import 只有 `SelfReflection`，**无 checker import**；重写循环 `:575` `if(!currentReflection.passed ...)` 用的是 `reflection.passed`（分数制）。
- `gwe-engine.ts:416-422`：生成后 `this.check()` 仅把 `checkResult` 挂返回值 + `emit('ai:done')`，**无循环消费它**。

> ⚠️ **修正结论：R3「升 checker error 逼自纠」当前机制是断的。** checker 的 `passed=!hasErrors` 与 reflection/orchestrator 的 `passed`（分数制）是**两套互不相连的 gate**。升 error 只会让 `checker.passed=false`，但重写循环不读它，照走 reflection 分数 gate。
> **R3 要真治本，必须先做「接线」前置步**：要么 (a) 让 `reflection/engine.ts` 消费 checker errors（转成 concern 拉低分数）；要么 (b) 让 `writing/orchestrator.ts:575` 同时卡 `checker.passed`（加 `&& checkerPassed`）。这一步 v2 原版漏写，已补入 §3 待核对 + 落地顺序。

**KB 阈值现状（修正旧清单错误前提）：**
- `Thresholds` 类型（`源码/types.ts:102`）**无字数/wordCount 字段**，字段覆盖锚点/填充词/段落/对话/句长/信息密度/五感。
- `MergedConfig`（`源码/types.ts:299`）有顶层 `wordCount: number` —— R4 字数检查应挂这里，不是 `thresholds`。
- `threshold_overrides?: Partial<Thresholds>`（`源码/types.ts:70`）确实存在，是 preset 可选顶层字段；但各 `preset_*.json` 当前主要用 `selections` 节点选择，**暂未发现 `threshold_overrides` 被实际填充**——KB 标定要先确认哪个 preset 用，不盲改。
