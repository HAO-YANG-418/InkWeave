# InkWeave 完整演进报告：从 Trea 构建到升级收口（2026-08-17 → 08-26）

> 说明：经实地核对项目记忆与 ` docs/历史评审/` 存档，本会话早期把 "Trea" 误判为「AI 视频剪辑工具」是错误。**Trea 是早期构建 InkWeave 的另一位 AI 协作体（实现方 / 代码方）**，与本项目的写作引擎是同一产物，并非独立产品线。本报告更正后按真实脉络撰写。

## 〇、Trea 到底是谁（先扳正误解）

| 项目 | 真实身份 | 证据 |
|---|---|---|
| Trea | 早期 InkWeave 的**实现方 AI**（用户把任务甩给它的「另一 agent」），负责 .ts/.json 代码落地 | `2026-08-17.md`「用户把评价文件喂给另一 agent（trea）」、`联合推进方案_WorkBuddy与trea.md`「trea = 实现方」 |
| WorkBuddy（本会话） | 验收方 + 度量方 + 协调方，后接手 #2 检测端 | 同上「WorkBuddy = 验收方 + 度量方 + 协调方」 |
| 用户（屿与雨） | 桥 / 拍板 / 实战写章 | 跨日志一致 |

结论：**InkWeave 一开始就是 Trea 写出来的**，后来 WorkBuddy 接手收口。不是「先用 Trea 做视频、再换 InkWe (写作)」。

## 二、Trea 时代的真实产物与局限

- **版本线**：v4.7（初始）→ v4.8（硬约束/网页面板）→ v4.9（反向闭环 v2 + quick-write）。
- **Trea 真做到的**：生成端 prompt 硬化（反例/正例/感官契约）、反向闭环机制（injectFingerprint）、网页面板（后依用户「删网页」指令移除）。
- **Trea 漏的（被 WorkBuddy 抓出）**：① error 不拦生成（写后审计架构上拦不住）；② 闭环是软建议非强制；③ 跨章/感官复发检测写了函数但**没接线**（零调用点）；④ 阈值打架（铁则≤45% vs 检测器 75%）；⑤ 网页壳进不了纯浏览器。
- 这些坑后来由 WorkBuddy 在 08-17~08-19 接手补齐。
