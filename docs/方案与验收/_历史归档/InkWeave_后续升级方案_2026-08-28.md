## 三、升级优先级（按「风险↓ / 收益↑」排序）

### P0 — 消架构债（⚠️ 非零风险，已打回，降级冻结）
- **U1 检测树吃 KB 阈值贯通 — ⚠️ 已打回，冻进"等真需要跨作阈值再开"**
  - 原设想"复用 config-merger 第4层已验证管道、零新架构风险"**不成立**（方案方核真身打回）：`check-chapter.ts:28` 明写"不 import mergeConfig…造最小 mergedConfig"，CLI 树**故意不接** config-merger；`checkChapter(text, targetWords, protagonistName)` 签名无 thresholds。
  - 真要做只有两条非零风险路径：(a) import mergeConfig 打破 CLI 编译隔离；(b) 给 checkChapter+执行器循环加 config 透传触碰已验证闭环。
  - **且 U1 治不了 D2**：质感多样性读硬编码词表 `TEXTURE_WORDS`（checkers.ts:375），非 Thresholds 字段，U1 只喂 Thresholds 碰不到词表。
  - 结论：不急做，等真有多作品跨作阈值需求再开。

### Y — 直接改 CLI 树过敏常量（最低风险真降噪，本次执行）
- 不改管道、不动已验证闭环，只放宽 CLI 树硬编码阈值：
  - `checkSenseDensity`：`totalWords > 500` → `> 1000`（感官密度过低字数下限放宽，短章不误伤）。
  - `checkTextureVariety`：`freq[w] >= 3` → `>= 4`（质感密集循环阈值放宽，"凉"等基调复用更不易触发）。
- 安全论证：只减少 warning、不增 error。CLI 树全 37 章 0 error 坐实（旧"error=0"指 CLI 树，经 CLI/源码分流实测成立）；`sense_density_low` 全 37 章 0 处（Y 未引入感官密度误伤）。inkweave check 的 error 来自源码树去 AI 味自检（cliche_reaction/simile_density），与 Y 无关。详见回归验证_Y降噪_2026-08-28.md §三。

### P1 — 降噪精准化 + 接口转正
- **U2 题材/风格节点级校准**
  - 把"过敏检测器"（质感多样性、开头锚点密度等）的放行阈值挂到对应 KB 节点 `threshold_overrides`，做到"按作品/题材放宽"。
  - 效果：消 D2，且不影响其他作品。
- **U3 LLM 语义层解冻验证**
  - 在有 provider 环境实跑 `checkDialogueSemantics`，验证对话碰撞/私心语义识别是否真准；通过则从"实验接口"转正，纳入生成自纠闭环。
  - 效果：消 D3，补全无动词上下文对话盲区。

### P2 — 概念统一（维护债清理）
- **U4 双树同概念检测合并为单一源**
  - 对话碰撞 / 私心：选定一方为权威源（建议 CLI 树正则作门禁权威、源码 LLM 作 async 增强），消除 D4 口径漂移。
  - 时机：与 U1 同步做最省（都是管道打通）。

### P3 — 能力增强（谨慎，先跑量再定）
- **U5 新检测器**（节奏曲线、爽点分布热力、章节钩子强度）——仅在十章实战积累真实数据后立项，不空调。
- **U6 自动预设推荐**——基于用户大纲自动匹配 17 预设之一。

## 四、分阶段路线

| 阶段 | 包含项 | 退出标准 |
|---|---|---|
| **阶段一（消债）** | U1 + U2 + U3 | 双树阈值同源；质感/锚点按节点校准；LLM 层 live 验证通过或明确冻结理由 |

## 五、风险与原则（升级过程不破已验证闭环）

1. **不盲加能力**：U5/U6 类增强项一律延后到阶段三，先消债。
2. **双轨独立核真身**：每步代码方交付后，方案方自跑门禁 + 读真身逐项钉死（本会话已建立此铁律）。
3. **不空调**：任何阈值/检测器调整，先基于真实章节数据（十章实战）再动，不凭空调参。
4. **降级安全**：LLM 相关改动必须保持"无 provider → 静默降级"不破门禁。
5. **单一真源**：KB 节点 `.kb.json` 是阈值唯一真源，禁止在代码里写死覆盖。
