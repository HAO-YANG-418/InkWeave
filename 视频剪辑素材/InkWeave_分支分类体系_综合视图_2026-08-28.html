1整体架构：多分支从哪来

InkWeave 不是单一 skill，而是「1 伞 + 3 子 skill + 共享底座」系统。"多分支"的载体是共享底座的 KB 节点树。

一句话：用户开一本书，先选 预设 → 系统按预设加载 22 维节点里的对应分支 → 风格自动成型，不需要用户懂写作理论。

2书怎么分类：22 维交叉

分两大块：① 书类型主轴（平台 × 题材 = 77 种）；② 风格味道（20 维风格分支决定）。

① 书类型主轴（2 维）

平台适配（7）：番茄 / 起点 / 晋江 / 七猫 / 飞卢 / 新媒体 / 通用

题材词汇（11）：玄幻 / 西幻 / 科幻 / 悬疑 / 历史 / 军事 / 电竞 / 都市 / 日常 / 灵异 / 通用

7 × 11 = 77 种书型 例：起点×玄幻 番茄×悬疑

② 风格分支（20 维）

视角语调句式节奏 段落密度描写修辞 战斗情感对话 锚点密度开头力度转折频率 结尾钩子爽点频率信息密度 目标字数严格度AI创意 AI续写长度填充词

20 维 × 各档选项 → 调出"味道"；与书型主轴交叉，形成完整一本书的风格签名。

3分支怎么用：选预设 → 自动加载

机制核心：每个节点的 threshold_overrides 双路消费、单一真源在 .kb.json。

① 选预设用户在大纲阶段挑一个命名风格（如「玄幻修仙-起点V3.1」）
→
② 生成 config产出 {项目}/书籍配置/{书名}.config.md，含 22 节点选择表
→
③ 写章加载写每一章时只加载被选中节点，风格自现
切换预设 = 重新生成 config，所有节点全切；双路走同一份 .kb.json，不会"教练说 A、门禁说 B"。
