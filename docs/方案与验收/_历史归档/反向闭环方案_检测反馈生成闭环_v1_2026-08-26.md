## §0 定义与目标

原待办定义："生成侧读取 health-report 矩阵自动调铁则"。

本方案把"写前分析 → 生成 → 写后检查"的**单向管道**，升级为"检测 → 反馈 → 生成"的**闭环**。但"自动调铁则"风险高（易震荡/过拟合现有章节风格），故 v1 分三档渐进，先做低风险的"读矩阵注入避雷提示"，暂缓自动调阈值。

## §2 设计原则

1. **低风险优先**：先做"读矩阵注入避雷提示"（不改铁则、不自动调阈值），避免过拟合 / 震荡。
2. **复用不重写**：`injectFingerprint` 是成熟基座，全局注入在其上**叠加**，不另起炉灶。
3. **可量化回归**：每次铁则 / 检测器改动都能用一条命令出前后违规 delta。

## §3 方案设计（三档）

### §3.0 补记：章间 reactive 闭环（已落地，纳入基线）

现状即基线。`injectFingerprint` 已把"上章刚犯的违规"注入本章契约（硬约束 + 反例 + 正例）。本方案**不改动它**，仅在文档正式记录，避免后续方案重复造轮子。

### §3.1 档1（必做·低风险）全局矩阵驱动注入

- **扩展 `pre-analysis.ts`**：新增 `readHealthMatrix(matrixPath?)` 读取 `health-matrix.json`，聚合全书每章 `violationCounts`，取加权 top-N（`error×3 + warning×1`）高频违规项，生成"全书级避雷清单"段落。
- **在 `injectFingerprint` 末尾合并调用**：上章查"刚犯"（单点 reactive）、全局查"常犯"（统计驱动），**去重**（全局项若已被上章禁忌覆盖则跳过）。
- **约束**：top-N ≤ 5；仅注入"可操作的避雷提示"（如"全书逗号链高发 → 本章维持每句≤8逗号、比≤3.0"），**不改铁则硬值**。
- **落点（代码方）**：`pre-analysis.ts:429 injectFingerprint` 末尾追加合并；新增 `readHealthMatrix()` 聚合函数。

### §3.2 档2（必做·中风险）闭环回归自动化

- **新增 `检测工具/verify-regression.ts`**（或扩展 health-report 加 `--baseline <path>`）：跑双树检测后，与 baseline 矩阵逐 `ruleId` 对比，输出 delta 表（如 `comma_chain error 12→2 净降83%`），并对"关键项不降反升"返回非零 exit。
- **用法**：改铁则 / 检测器前 `cp health-matrix.json baseline.json`；改后跑 `npx tsx 检测工具/verify-regression.ts --baseline baseline.json`，一条命令出前后对比，替代人工跑 + 肉眼读。
- **落点（代码方）**：`检测工具/verify-regression.ts`（新文件）。

### §3.3 档3（暂缓·高风险）阈值自适应

- **暂不自动调 `default.json` 阈值**。理由：阈值人工标定更可控，自动调易震荡 / 过拟合现有章节风格。
- **留接口**：`health-matrix` 已产出统计；未来可基于"人工审核 + 批量调 `threshold_overrides`"半自动，不在 v1。

## §6 风险与边界

- **全局注入防过度约束**：top-N 限 5、去重，避免 LLM 被过多"禁忌"压垮信号（`pre-analysis.ts:619` 已强调"合并为单一契约避免信号分裂"）。
- **阈值自适应不自动化**：v1 不动 `default.json`，防震荡。
- **不碰生成铁则硬值**：全局注入只加"提示"，不改 `thresholds`。
- **矩阵依赖**：档1 需要 `health-matrix.json` 存在；若不存在则优雅降级（仅保留上章 reactive，与现状一致），不报错阻断生成。
- **档1 聚合字段须对齐矩阵真结构**：`readHealthMatrix` 聚合每章 `violationCounts`（按 ruleId），动手前先核 `health-report.ts:108/:191` 导出的键名与章节键名，避免聚合错位——这是档1 唯一易踩的实现坑。
- **档2 优先 diff 两份矩阵而非复跑检测**：直接吃 `current` vs `baseline` 两份 `health-matrix.json` 做逐 `ruleId` diff；复刻 health-report 双树检测逻辑既不省事又易分叉。矩阵不存在时优雅降级。
