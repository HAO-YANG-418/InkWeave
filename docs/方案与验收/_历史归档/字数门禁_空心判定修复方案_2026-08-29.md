> 面向代码方。问题由跑量剖面采集时的实测暴露，已用全 40 章扫描坐实。

## 一、问题：本该拦"写空"的 error，从未生效过

`检测工具/checkers.ts:1194-1218` `checkWordCountTarget()`：

```ts
if (ratio < 0.9) {
  const sensoryTotal = visual + auditory + tactile + olfactory + gustatory;
  const isHollow = sensoryTotal < 3 && stats.anchorCount < 3;   // ← 门槛
  if (isHollow) { /* error：拦写空 */ }
  else { /* warning：「短而密，放行」 */ }
}
```

**全 40 章实测命中：`hollow = 0 / 40`。** 最短的 ch37（927 字，完成率 31%）也照样放行。

### 根因：门槛比真实值低 20–30 倍，且是 `&&`

| 章 | 字数 | 五感合计 | 锚点 | 门槛(3) | 结果 |
|---|---|---|---|---|---|
| ch36 | 925 | 50 | 25 | 3 | ⚠️放行 |
| ch37 | 927 | 61 | 28 | 3 | ⚠️放行 |
| ch39 | 2167 | 78 | 77 | 3 | ⚠️放行 |
| ch40 | 2231 | 100 | 85 | 3 | ⚠️放行 |

`sensoryTotal < 3 && anchorCount < 3` 是**与**关系，任一达标即放行；而真实章节这两项在 **18–100** 区间。等于这条规则**在真实写作中恒为 false**。

## 二、⚠️ 反直觉发现：改用「密度」判空同样无效（推翻我上轮建议）

我上一轮建议"改用密度（五感/千字、锚点/千字）判空"。**实测证明这个方向是错的**——因为**短章的密度反而更高**：

| 章 | 字数 | 五感/千字 | 锚点/千字 | 与中位数比 |
|---|---|---|---|---|
| ch36 | 925（31%） | **54.1** | 27.0 | 五感**高于**中位 42.8 |
| ch37 | 927（31%） | **65.8**（全样本最高） | 30.2 | 五感**最高** |
| ch35 | 1163（39%） | 43.9 | **50.7**（全样本最高） | 锚点**最高** |
| ch33 | 1493（50%） | **58.9** | 34.8 | 五感**高于**中位 |
| 全样本中位 | 2648 | 42.8 | 31.9 | — |

**短章因为不注水，单位密度反而更高。** 所以任何基于密度的阈值都抓不到它们：

| 候选阈值（hollow = 五感/千字<X && 锚点/千字<Y） | 命中章数 |
|---|---|
| X=15, Y=8 | **0 / 40** |
| X=20, Y=10 | **0 / 40** |
| X=25, Y=12 | **0 / 40** |
| X=30, Y=15 | **0 / 40** |

**结论：写空的章不是"密度低"，而是"绝对量小"。** 密度判空此路不通，我上轮的建议作废。

## 三、真问题：错不在阈值，在放行逻辑本身

"短而密放行"的设计初衷是**保护精炼好文不被误判**。但它把两件事混为一谈了：

- 铁则十九「内容密度」的本意 = **不注水**（反对的是水），
- 现行规则实际效果 = **可以写短**（放行了短）。

对网文而言这大概率是**错的**：章节字数是有商业含义的（影响推荐/订阅/读者预期），"精炼"通常不抵"太短"。ch36/37 只有 925 字仍被判"合格"，就是这条规则直接造成的。

## 五、建议改动（方案 B，供代码方实施）

```ts
// checkers.ts checkWordCountTarget()，替换 ratio<0.9 分支
if (ratio < 0.7) {
  // 绝对下限：不论密度，过短即不合格（写空兜底）
  violations.push({
    ruleId: 'word_count_hollow', ruleName: '字数过短（写空）',
    message: `实际字数${stats.totalWords}，目标${target}字，完成率仅${(ratio*100).toFixed(0)}%，低于70%下限，判定写空。`,
    severity: 'error',
    suggestion: '补充场景与细节至目标的70%以上。短而密不再豁免：密度高只证明不注水，不证明篇幅达标。',
  });
} else if (ratio < 0.9) {
  // 70%–90%：沿用密度豁免，但门槛改为密度口径（不再用绝对值3）
  const sPerK = 1000 * sensoryTotal / stats.totalWords;
  const aPerK = 1000 * stats.anchorCount / stats.totalWords;
  const isHollow = sPerK < 25 && aPerK < 12;   // ≈P10 的一半，宽松
  violations.push(isHollow
    ? { ruleId:'word_count_hollow', severity:'error', /* 空心 */ }
    : { ruleId:'word_count_short', severity:'warning', /* 短而密放行 */ });
}
```

## 六、✅ 决策定稿（方案方拍板 2026-08-29，待代码方实施）

| 决策项 | 结论 |
|---|---|
| 方案 | **B（分层）** |
| 下限 | `ratio < 0.7`（<2100 字）→ error，不论密度 |
| 0.7–0.9 | 沿用密度豁免，门槛改密度口径 `sPerK < 25 && aPerK < 12`（≈P10 的一半，宽松） |
| 生效范围 | **全局生效，不设章号开关** |
| 存量 7 章 | **如实报错，不追溯豁免** |

### 为什么放弃"只对 38 章后新章生效"（推翻我上一版建议）
1. **需要额外的"章号开关"机制**（配置 `enforceFromChapter` 之类），属新架构负担，与"不增加复杂度"相悖。
2. **同一项目两套标准**，规则不自洽，后续任何回归都要先判断"这章算新还算旧"。
3. **最要命的一条**：为让存量 7 章继续显示全绿而留豁免通道，本身就是"假放行"——**正是本方案要治的病**。

### ⚠️ 必须同步更正的旧结论
此前"CLI 树全 37 章 0 error"是在**失效规则**下测出的**虚假全绿**。规则修好后，全量重跑会如实暴露 7 章 error（ch32/33/34/35/36/37/38）。
这不是回归失败，是检测器终于开始干活。对外表述需改为：**"旧规则下全绿（规则失效）；新规则下 7 章因写空报错，属实报。"**

### 方案方配套动作
- ch38（1541 字 < 2100）会落入 error。方案方**主动补写至 2100+**，按铁则十九"加有营养的内容"而非硬凑，使跑量批次 38–40 全部符合新标准。

## 九、⚠️ 遗留：源码树密度分支是死代码（待定）

### 9.1 实测：两树感官词典口径差 1.62 倍
跑 `_sandbox/_density_scan_src.mts`（可复现），全 47 章双口径：

| 口径 | min | P10 | P25 | 中位 | P75 | max |
|---|---|---|---|---|---|---|
| CLI树 五感/千字 | 19.9 | 21.8 | 33.2 | 40.9 | 45 | 65.8 |
| 源码树 五感/千字 | **44.6** | 52.2 | 59.7 | 68 | 77.1 | 98.5 |

源码÷CLI 倍数中位 **1.62**（1.28–3.7）。字段名：CLI `visual/auditory/tactile/olfactory/gustatory`，源码树 `sight/sound/smell/touch/taste`。

### 9.2 结论：源码树 `sPerK < 25` 永不触发
源码树口径 **min=44.6 > 25** → 阈值 25 命中 **0 章**，放到 40 仍命中 0 章。
→ **源码树「0.7–0.9 密度豁免」分支是死代码**，源码树对 2100–2700 区间**毫无密度判空能力**。本次 6 章 error 全走"低于硬下限"分支才未暴露。

要让它活需 >44.6：取 45 → 命中 ch41；取 50 → 命中 ch17/ch22/ch41（后两章 >2700 不走该分支，实际只新增 ch41）。

### 9.3 更深的根因（与 texture_variety 同类）
ch41 是**对话密集章**（审问陈默），两树口径密度均为全样本最低（CLI 20.4 ≈ min；源码 44.6 = min）。
→ **以"感官密度"判空会系统性惩罚对话密集章**，与本文档 §二 记录的"texture_variety 把对话里的质感词计入"是同一类口径缺陷。

### 9.4 建议
- **治本**：`texture_variety` 与「密度判空」两处**都改为只统计叙述段（`p.type === 'narrative'`）**，排除对话后重新标定阈值。两个阈值才真正有意义，也不误伤对话戏。
- **过渡**：硬下限 2100 已在做主要工作，密度分支可暂不动；但代码注释「0.7–0.9 沿用密度豁免」已失真，建议改为「该分支在源码树口径下当前不触发（源码树五感口径约为 CLI 的 1.6 倍），待口径统一后启用」。
