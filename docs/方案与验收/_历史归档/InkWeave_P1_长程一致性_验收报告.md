# InkWeave P1 · 长程叙事一致性（v5.0）验收报告

> 日期：2026-08-21
> 目标：补齐最大短板——跨章事实一致性（相对 Sudowrite 我们原 1/5，现补规则级事实指纹闭环）

---

## 一、做了什么

### 1. 新增事实抽取模块 `检测工具/extract-entities.ts`
纯规则、确定性、不依赖 LLM（避免长文成本高/不稳）。从「项目设定档案 + 本章正文」抽取事实指纹 `ChapterFact`：
- **characters**：从角色档案抓已知角色，用 `text.includes(name)` 判定本章是否出场（中文无词边界，角色名唯一性强，比边界正则更可靠）。
- **timeAnchors**：抓第N日/凌晨/清晨/夜晚/时刻/时长等时间信号。
- **properNouns**：从世界观设定档案抓专名 + 正文大写专名候选。
- **pendingForeshadow**：抓铁则十假钩子句型 + 秘密/未知/其实句式。
- **numericAnchors**：数值+单位锚（供数值一致性）。

### 2. 新增跨章事实校验 `checkCrossChapterFacts`（`checkers.ts`）
读上章 facts 与本章程式比对，**全 warning 级，宁缺毋滥**：
- `fact_time_conflict`：上章夜晚锚 → 本章直接白昼信号无过渡。
- `fact_char_state`：上章 present 角色，本章出现断臂/瞎了/死亡等极端状态无交代。
- `fact_foreshadow_drop`：上章有未回收伏笔，本章既不回收也不延续。
- `fact_noun_variant`：上章设定专名，本章疑似变体写法。

### 3. fingerprint 扩展（`check-chapter.ts`）
`--save-fingerprint` 分支新增 `facts` 字段，保存事实指纹。检测调度新增 `checkCrossChapterFacts` 接入（上章 facts → 本章校验）。

### 4. pre-analysis 事实约束注入（`pre-analysis.ts`）
写前分析新增「🟢 长程事实约束」段：注入上章出场角色（保持状态连续）、时间锚（时间推进需过渡）、未回收伏笔（本章至少回收/延续一条）。

### 5. 工程化
- 版本号报告头统一 v5.0（checkers.ts / pre-analysis.ts）。
- 补 8 个单元测试（`checkers.test.ts`），覆盖 extract + 4 类校验的正负例。
- 全部 warning 级，error 级只保留原有硬伤（破折号超额度/排比≥6/假钩子）。

## 三、已知边界（诚实标注）

1. **事实指纹是规则级，不是语义级**。角色状态只检极端词（瞎/死/断臂），不检"心情/立场/关系"漂移；伏笔只检句型，不检语义悬念。语义级需后续接 LLM 兜底（方案中已规划，本期未做，避免成本/不稳）。
2. **专有名词突变检测保守**：仅当上章专名完全不出现且正文出现同首字变体才报，避免误杀正常省略。可能漏检纯概念漂移。
3. **伏笔回收依赖句型**：若作者用非标准句式埋/收伏笔，可能漏记。宁缺毋滥原则下优先不误杀。
4. **中文角色 present 用 includes**：极端情况下"林深山"之类会误判，但角色名唯一性高，实测无问题。
