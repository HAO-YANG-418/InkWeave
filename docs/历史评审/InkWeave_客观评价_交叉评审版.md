## 0. 一句话结论

**骨架与工装是专业级，文风与交付是 demo 级。** 架构设计（认知分离 + 程序化门禁）真实扎实、工程闭环可跑；但输出风格高度单一（"堆砌递进体"）、生成与检测两张皮、流程过重且未打包成可交付产品——前者值得骄傲，后者决定能否卖出去。

## 3. 客观优点（真强，非客套）

1. **认知分离架构（9）**：写作用时只加载创作规则，检查交给工具——解决"AI 一边写一边自我审查导致平庸"。
2. **程序化门禁防跳步**：大纲 5 门禁 + 设定 3 门禁；**冷却检测**（54 个反套路模板）直击网文撞模板痛点，是差异化亮点。
3. **工程闭环真实（8）**：质量指纹跨章传递；第14章 fingerprint 真实抓出逗号链、感官失衡、数据锚点过高、"不是X是Y"句式，说明检测在干活。
4. **知识库模块化**：22 节点×95 选项 + 17 预设，风格可切换不重写——产品化基础。

## 4. 客观问题（按严重程度排序，附证据）

### 4.1 【最严重】输出风格高度单一——"堆砌递进体"（4 分）
- **证据**：第14章《溯源》几乎整章被以下句式统治：`穿过X，穿过Y，穿过Z`、`往X里流，往Y里流`、`不是…是…`、`和…一样` 密集比较。
- **判断**：作为高潮章（母体揭秘）有冲击力；作为常态化写法，读 3500 字易疲劳。引擎把"递进堆叠"编码成强偏好，缺乏节奏多样性。
- **接手评审请验证**：抽查其他章节（如第10/11/12章）是否同样句式统治；判断是否仅高潮章特性。

### 4.2 生成与检测"两张皮"（闭环未打通）
- **证据**：第14章 fingerprint 标了 `not_shi_pattern`(warning)、`comma_chain`、`data_anchor_high(21.1/千字)`、`sense_density(视觉占比过高)`，但生成端照样大量产出。
- **判断**：fingerprint 目前只记录 errors/infos，**未反向约束下一章生成**；检测是事后纠错，非事前约束。

### 4.3 知识库节点未真正生效
- **证据**：有"感官变奏"节点，但第14章视觉 89 次占比过高、其他感官几乎没用；"数据锚点"同样泛滥。
- **判断**：节点在 generation 时未被落实。

### 4.4 流程过重（3 分）
- 大纲 15 步 + 5 门禁 + 逐段推演，写章三阶段。对硬核作者都累，对卖课目标人群（抖音电商、非技术）几乎不可用；且依赖 `npx tsx`。

### 4.5 分发/打包断档（3 分）
- 仅项目内 `.md`，未装成 WorkBuddy skill，无 MCP / 网页壳。要"卖课变现"，交付形态不成立。

### 4.6 版本还在震荡、模块不同步
- 证据：主 SKILL 写 v4.6、写作/大纲写 v4.7、设定写 v4.6；v4.5.2 自承 "Self-Refine 验证无效"。说明仍在试错期、未收敛。

### 4.7 效果无度量（2 分）
- "18 检测器 / 54 冷却 / 22×95" 均为宣称，无 A/B 数据证明优于 baseline。卖课时讲不出"完读率/追读提升 X%"。

## 5. 改进建议表（按性价比）

| 优先级 | 建议 | 理由 |
|---|---|---|
| 高 | **风格多样性硬约束**：生成指令加"排比堆叠上限"——单章"穿过/往…流"类句式 ≤N 次、连续递进句占比封顶 | 治最大病 |
| 高 | **检测→生成反向闭环**：每章检测后，把最频繁 2–3 类 warning 写入下一章"本章禁忌"（扩展 fingerprint） | 当前指纹不约束生成 |
| 高 | **轻量模式**：非硬核用户跳过逐段推演、只跑关键门禁，并把 `npx tsx` 藏进壳 | 否则目标人群用不了 |
| 中 | **感官/量化 hard gate**：sense_density、data_anchor 从 info 提为 warning 并设阈值 | 落实已有节点 |
| 中 | **打包成可装 skill / MCP / 网页** | 卖课前置条件 |
| 中 | **统一模块版本号**，停止周更大版本 | 显得稳 |
| 低 | **建效果度量**：抓 10 章盲评对比 baseline | 卖课弹药 |
