## 二、动作 ②：碎句双树对齐（段落感知，消鼓点误伤）

- 取证：CLI 树 `检测工具/checkers.ts` 的 `checkShortSentenceFragments`（line 780）**已有鼓点放行逻辑**（含动作/感官动词或落对话段内则放行），但它是**按句子连续 run 计数、不区分段落**；源码树 `checker.ts` 的 `碎句病`（line 995）是**"同一段落内连续短句"**计数。
  → 同一段"一篇一段"的刻意鼓点（各占一段），CLI 树跨段累加成 run≥3 触发、源码树因"各占一段"不触发 = **双树不一致、误伤鼓点**。
- 修复：把 CLI `checkShortSentenceFragments` 改为**段落感知**——run 只在同段内累加，跨段短句不累加成 run，与源码树口径对齐。
- 安全论证：该改动**只会减少 warning、绝不会新增 error**（不降低任何"段内真碎句"的捕获门槛），对门禁零回归。

## 三、动作 ③：开头锚点双计 bug 修复（真 bug，非误判）

- 取证：方案方观察到的"`开头缺锚点` 每章报 2 次"——全仓 grep 只有 `源码/checker.ts:939` 一处 push `开头缺少身体锚点`（ruleId `opening_no_body`），却出现两次，说明是**同一函数被调两次**。
- 根因：`check()` 在 **line 171（检查项9）** 和 **line 236（检查项22）** **两次调用同一个 `checkOpeningImpact`**，两次都受同一 `disabledChecks.has('opening_impact')` 守卫，未禁用即跑两遍 → 开口警告被 push 两次。检查项22 注释"开头力度检测"但调用的仍是同一函数，纯重复。
- 修复：删除 line 234-237（检查项22）的重复调用，保留检查项9。开口检测能力完整保留，仅不再双计。

## 四、动作 ④：质感多样性**不盲放宽**（决策与理由）

- 取证：`检测工具/checkers.ts` 的 `texture_variety`（line 370）触发条件为"同质感词连续2句且全章≥3次"或"单词全章≥6次且压过其余"，`凉` 在 `TEXTURE_WORDS` 内。
- **决策：不盲放宽全局常量**。理由：
  1. `凉` 是《裂日》冷感基调的刻意复用，放宽全局常量 = 让**别的作品**真·循环腔也放行，伤害其他作。
  2. 这本质是**按作品校准**问题，正确归属是 **② 接 kb**（per-work threshold_overrides），不是全局数字游戏。
  3. 与方案方"别空调/先取证再动刀"的纪律一致：盲改验证闭环上的全局常量 = 重蹈过度诊断。
- 处置：作为已知债挂入 ② 接 kb 任务，不在本轮回动。
