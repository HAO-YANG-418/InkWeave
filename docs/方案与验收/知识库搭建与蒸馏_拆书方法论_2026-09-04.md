## 一、什么是「拆书」（网文写作语境）
拆书 ≠ 抄剧情，是**把爆款书当"结构图"拆开**，偷它的框架、换自己的血肉。网文圈公认学写作的捷径。

### 1.1 主流拆法（我学到的）
- **八步拆解法**：选对目标（大神作 / 近期爆款，别碰风格特殊的）→ 带目的通读两遍 → 拆大纲章纲（每章 50-100 字概括：核心事件 / 伏笔 / 爽点）→ 叙事时间线（插叙倒叙）→ 人设档案（性格 / 背景 / 优缺点 / 弧光 / 金手指）→ 感情线与人物关系 → 总结核心技巧（爽点节奏 / 情绪推进 / 伏笔埋收）。
- **四步法**：扒章纲（看骨架）→ 拆结构（看节奏：前三章完成"主角出场 + 冲突引爆 + 钩子"）→ 拆爽点（在哪 / 怎么铺垫 / 怎么释放）→ 提炼可复用模板。
- **暴力拆书法（一张 A4 纸）**：立项（核心拷问：切中什么心理痛点 / 核心爽点机制）→ 画骨（前 50 章结构图）→ 炼金（合书用大白话写"谁和谁矛盾 / 怎么让你气怎么让你爽 / 结尾什么悬念"）→ 合（总结出公式，如"极致危机压迫 + 极简杀伐果断 + 肌肉碾压 = 颅内高潮"）。
- **拆书四维度（智语写作）**：爽点（代入感 > 期待感 > 高潮，情绪闭环）/ 人设 / 剧情推进逻辑 / 可复用技巧。

### 1.2 行业沉淀的"结构密码"（可直接复用）
- **黄金三章**：第 1 章冲突暴击（200-500 字内抛绝境，不铺垫世界观）；第 2 章金手指觉醒；第 3 章首次打脸（小爽闭环），章末留钩子。
- **爽点公式**：抑（反派狂踩）→ 等（暗中蓄力）→ 爆（极限反转 / 一招制敌）→ 奖（情绪 + 实质收益）。每 2-3 章小爽点，每 10 章中高潮，每 30 章大反转。
- **反转四招**：逻辑误导（行为不变变动机）/ 人设底色置换（A 面温暖里埋 B 面）/ 多重套娃（假象→真相→真相是另一假象的掩护，最终解释前面所有不合理）。
- **画面感四法**：具体名词替形容词 / 远景→中景→特写 / 长句拉弓短句放箭 / 至少两种感官（触觉嗅觉最易被忽略）。

## 二、知识库该长什么样（工程化参考，我学到的）
- **Lorn.NovelWriteSkills（GitHub 开源写作资产库）**：分层 = 通用 skills（跨题材能力本体）/ 题材目录（.github/skills 包装层 + prompts SOP + instructions 局部规则）/ scripts（质检门禁）。强调"结构化、可迁移、可终检、可持续迭代"。它的"蒸馏"产三类模板：①作者文风 DNA（句长基线 / 段落节奏 / 感官偏好 / 比喻指纹 / 禁忌清单）②作品蓝本 DNA（章首模式指纹 / 钩子轮换规律 / 回报间隔 / 节奏分布）③写作研究模板（题材 × 平台默认约束）。统一注册，下游 skill 自动消费，优先级：用户指定 > 写作研究 > 通用默认。
- **外部记忆（Arsturn / Sudowrite）**：长篇 LLM 有"失忆症"——解法是 Series Bible / Story Bible / Lorebook（触发词注入），相关事实按需注入当前场景，而非塞进超长 prompt。
- **openclaw 案例教训**：建三库（拆文库 / 写作库 / 审核库）+ 两智能体（写作 / 审核）流水线；直接聊天产出"狗屎"，必须知识库 + 门禁。

## 三、蒸馏三档（从语料到可消费知识）
| 档位 | 做法 | 我们现状 | 优点 | 缺点 |
|---|---|---|---|---|
| 规则化 | 人读拆书 → 写铁则 / node | 铁则二十四 / 二十五（手写） | 可解释、可审计、稳 | 覆盖慢、靠人 |
| few-shot | 拆书片段作高质量示例，按 题材 × 位置 检索注入 | 未做（示例库空） | 贴真书节奏、零训练成本 | 占 context |
| 微调 | 拆书场景作续写 pair | finetune_prep 9 pair | 分布级治本 | 需算力 / 授权 / 版权 |

参考 DeepWiki 的 ExampleLibrary：按 genre / style / section_position 两阶检索，quality_threshold 0.75 自动存优段，生成时注入 few-shot。

## 四、我们的落地草案（拆书注入现有架构）
**现状 gap**：我们现在 `corpus/` 是"仿写"样本，不是"真拆书"产物。仿写能凑字数过质检，但学不到真书的节奏密码（钩子轮换、回报间隔、反转套娃）。
**升级路径**：
1. 用拆书法对 8 本做系统拆解 → 产出**元件卡库**：母题卡 / 桥段卡（打脸 / 装逼 / 解密模板）/ 爽点节奏卡（间隔分布）/ 开篇公式卡 / 金句范式卡。
2. 跨书聚合同维度卡 → 归纳通用铁则 + 题材专属节点（preset）。
3. 蒸馏三路并行落点：铁则(node, 人审) + few-shot 示例注入(生成时按题材 × 章节位置检索) + 微调 pair(finetune_prep 扩量)。
4. **好懂直白硬标准过滤**：所有拆书产物过一遍"零理解负担"红线，剔除文学化 / 晦涩表达。

## 五、关键约束（不能碰）
- **版权**：只能拆公开试读 + 合规样本，不能拆全文。真拆全文需路径二（你授权正版 txt）。
- **单书过拟合**：拆一本容易学成它的腔；必须跨 8 本归纳通用规律，保留风格可选性。
- **好懂直白不可让位**：拆书学到"文学性"表达要被红线过滤，不能回潮冷薄碎。

## 六、待你拍板（讨论焦点）
1. **拆书颗粒度优先级**：先拆哪层？母题级（大结构）/ 桥段级（可复用模板）/ 句法级（金句范式）。我建议桥段级优先（最贴"出货好懂"）。
2. **拆书来源**：路径一（合规样本，够用但浅，零成本）vs 路径二（你授权正版全文，真拆但需你给文件）。你之前说"不买书不操作"——是否愿意为"真拆"破例授权已有的正版 txt？
3. **KB 形态**：现状纯规则铁则 vs 加元件卡库（结构化 Markdown）vs 加向量 RAG（检索增强，按场景召回）。是否要上 RAG？
4. **蒸馏落点权重**：先人审铁则（稳、可审计）vs 直接上微调底座（治本但需算力 / 授权）。当前阶段我倾向"铁则 + 示例库"先跑，微调放软件化阶段。
