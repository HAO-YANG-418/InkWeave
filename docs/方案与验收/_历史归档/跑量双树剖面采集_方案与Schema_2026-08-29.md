# 跑量 · 双树剖面采集 —— 方案与 Schema（2026-08-29）

> 目的：为 U2（KB 数值阈值校准）解冻准备 **per-work 实测数据地基**。
> 铁律：没有 per-work 实测就给 KB 填数值 = 空调（用户已拍板"先跑量再调参"）。
> 本轮定位：方案方定 scope + Schema，代码方搭采集脚本/流程并开跑。

---

## 一、Scope 决策（已定，无需再议）

### ① 跑什么：**续写新章**，不重写旧章
- 范围：**第 38–47 章**（10 章，接续 28–37 实战批次之后；大纲只到 15，后续本就自创）。
- 理由：重写旧章测的是"改后 vs 改前"，对 U2 数据价值低；续写新章给出**当前引擎态的干净 per-work 剖面**，能同时验证"写空/AI 味治理"到底有没有效。

### ② 用什么入口测：**双跑**（CLI 验收树 + 源码生成树）
- 理由：U2 将来要动的是**源码树数值阈值**；而"凉"在 **CLI 树词表**。两张剖面都得有，才分得清"哪类是数值可调、哪类是词表误伤"。
- 数量：10 章足够，多了是凑数。

### ③ 其它优先方向
- 视频素材库（视频剪辑素材/）属 **clip-assistant** 产品线，不阻塞本任务，本轮不碰。
- 无其它优先方向，按跑量推进。

## 二、双树口径（钉死，采集时严格分流）

| 树 | 入口 | 你（用户）已核实的事实 | 采集关注点 |
|---|---|---|---|
| **CLI 验收树** | `npx tsx 检测工具/check-chapter.ts "<章>" --target 3000 --project 裂日` | Y 降噪所在；全 37 章 **0 error**；`sense_density_low` 全 0；`texture_variety` 仅 warning | `sense_density_low`、`texture_variety`(warn)、`排比堆叠`(error)、`word_count_short`、**凉 FP**（TEXTURE_WORDS 在仙侠/天气语境的误伤计数） |
| **源码生成树** | `源码/checker.ts` 经 `gwe-engine` 或 R1 合并入口（生成时自检） | 去 AI 味自检；`inkweave check` 显示的 error 全来自此树（`cliche_reaction`/`simile_density`） | `cliche_reaction`、`simile_density`、`fake_reactions`、其它去 AI 味项、**写空/空洞**相关 |

> 关键：两树的 violation 必须**带 tree 标签**分开落表，绝不能合并成一个数再去"戳破/验证"，那是上轮口径错误根源。

## 三、剖面表 Schema（采集脚本的输出格式）

每张表 = 10 行（38–47），每行一个章节。建议 CSV/Markdown 双出，便于你直接填 KB。

### 列定义
| 列 | 含义 | 来源树 |
|---|---|---|
| `chapter` | 章号 38–47 | — |
| `word_count` | 实际字数 | 两树共用 |
| `target_words` | 目标字数（默认 3000） | — |
| `cli_error_total` | CLI 树 error 总数 | CLI |
| `cli_warn_total` | CLI 树 warning 总数 | CLI |
| `cli_sense_density_low` | `sense_density_low` 命中数 | CLI |
| `cli_texture_variety_warn` | `texture_variety` warning 数 | CLI |
| `cli_paibei_stack_err` | `排比堆叠` error 数 | CLI |
| `cli_word_count_short` | `word_count_short` error 数 | CLI |
| `cli_liang_fp` | "凉"在仙侠/天气语境的 TEXTURE_WORDS 误伤计数（**注：Y 降噪 3→4 并未吸收它，见 §四**） | CLI |
| `src_error_total` | 源码树 error 总数（= inkweave check 显示的 error） | 源码 |
| `src_warn_total` | 源码树 warning 总数 | 源码 |
| `src_cliche_reaction` | `cliche_reaction` 命中数 | 源码 |
| `src_simile_density` | `simile_density` 命中数 | 源码 |
| `src_fake_reactions` | `fake_reactions` 命中数 | 源码 |
| `src_other_ai_flavor` | 其它去 AI 味项合计 | 源码 |
| `u2_numeric_tunable` | = `src_cliche_reaction + src_simile_density + src_fake_reactions + src_other_ai_flavor`（**U2 唯一能动的数值项**） | 源码 |
| `u2_wordlist_only` | = `cli_liang_fp`（**U2 数值阈值碰不到，必须另立机制**） | CLI |

### 采集脚本职责
1. 对每个 38–47 章，分别调 CLI 树与源码树，取 `violations` 数组。
2. 按 `ruleId` 聚合计数，落入上表对应列。
3. `cli_liang_fp` 需做轻量语境判定（"凉"前后 N 字是否含仙侠/天气/灵气类词），计数误伤。
4. 输出 `剖面_38-47.md` + `剖面_38-47.csv`，落 `docs/方案与验收/`。

## 四、U2 解冻触发条件（数据到位后判）
- 若 `u2_numeric_tunable` 在某类 ruleId 上**系统性偏高且分布稳定** → 可给 KB `threshold_overrides` 填该数值（仅源码树生效）。
- 若 `cli_liang_fp` 持续 > 0 → 坐实"凉"误伤真实存在，U2 数值阈值无解，需走"节点排除词表"机制（非本轮）。
- 若 `cli_error_total` 出现 > 0 → 先查是否新引入的真实质量 error，不归 Y 降噪。

### ⚠️ 已实测推翻的假设：Y 降噪 3→4 **不能**兜底"凉"
`texture_variety`（`检测工具/checkers.ts:375-419`，`TEXTURE_WORDS` 含"凉"）有**两条**触发路径，Y 降噪只改了其中一条：

| 路径 | 条件 | Y 降噪是否改动 |
|---|---|---|
| ① 密集循环 | 同词在连续 2 句出现 且 全章 ≥4 次 | ✅ 改了（3→4） |
| ② 单调霸权 | 某词全章 ≥6 次 且 **> 其余质感词频次总和** | ❌ **未动** |

**ch37 实测**：「凉」占 18 句、其余质感词总和仅 4 → 路径②（18≥6 且 18>4）✅触发、路径①（凉@10,11,16,17,18）也触发 → `cli_texture_variety_warn=1`。
→ 18 句远超阈值 4 与 6，改 3→4 根本没碰到它。**"Y 降噪 3→4 作凉兜底"不成立，凉误伤至今每章都在报。**

**ch38 实测**：已刻意压到 `cli_liang_fp=6`（且本章场景为锅炉房、"凉"是克制残频的核心武器，主题上必须使用）仍 `warn=1`。

**ch39 实测（反向证据，修正上述推论）**：「凉」压到 FP=4 且让其余质感词（黏/涩/酸/麻/木）分散分布后，**`cli_texture_variety_warn = 0`**。

| 章 | 凉 句数 | texture_variety |
|---|---|---|
| ch37 | 18 | warn=1（确属过量，抓的是真毛病） |
| ch38 | 6 | warn=1（边界） |
| ch39 | 4 + 分布均衡 | **warn=0** |

### 再校准后的 U2 结论
- 「Y 降噪 3→4 在**高用量**（18 句）下无效」→ **仍成立**：18 远超阈值 4 与 6，改 3→4 没碰到它。
- 「必须走节点排除词表」→ **降级为可选项，非必须**。texture_variety 在凉约 4–6 句处有区分度，**可通过控用量规避**；节点排除词表本质是"给裂日放宽凉额度"的便利手段，不是"不修就每章报错"的硬故障。
- 诚实 caveat：凉是裂日核心概念词（克制残频的武器），要求作者每章压到 ≤4 句是真实创作约束。放宽与否属**产品判断**，而非技术故障——且现在已有三点数据可判。
