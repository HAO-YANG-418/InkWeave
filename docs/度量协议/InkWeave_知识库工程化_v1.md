## 一、改了什么

### 1. `检测工具/pre-analysis.ts` — 新增「第0步：风格配方」
- `loadBookConfig()`：读取 `项目_X/书籍配置/X.config.md`，提取**预设名 + 22 节点选项**（按项目短名精确匹配 config 文件，不再误取同目录其他书配置）。
- `loadPreset()`：读取 `知识库/预设/<预设>.md`，抽取「核心指令 / 约束规则 / 专属词汇」并注入。**带后缀容错**（配置写 `玄幻修仙-起点V3.1追读版（荒古纪元调校版）`，实际文件名无后缀，自动按前缀匹配）。
- `step0StyleRecipe(chapterNum)`：输出每章风格配方，含：
  - 本书预设核心指令（之前完全没进生成）
  - 预设硬约束快照：视觉≤45% / **触觉≥视觉** / 锚点每200字≥1 / 数据锚点适中 / 信息密度每1000字≥4
  - **每章多样性轮换**（章号驱动，对抗"堆砌递进体"单调）：
    - 主导非视觉感官在 [触觉/听觉/嗅觉] 间轮换
    - 修辞变奏：奇偶章在「纯白描 / 允许1处非常规修辞」间轮换
    - 镜头侧重在 [动作/环境/心理] 间轮换
  - 已选节点表（风格锚）
- 在 `main()` 顶部调用，作为写前第一环（门禁#0：未读预设禁止进第1步）。

### 2. `检测工具/checkers.ts` — 把预设特有硬约束补成真检查
- **触觉≥视觉**：`checkSenseDensity` 内新增 `sense_tactile_below_visual`（warning），落实预设"非视觉感官必须压过视觉"。
- **锚点密度**：新增检测器 `checkAnchorDensity`（warning），每200字≥1 个身体/具体锚点，注册进「统计密集型」组。之前只计数不校验。

### 3. 修复 dist 路径旧坑
- `ROOT = path.resolve(__dirname,'..')` 在 dist 下变成 `dist/`（dist 不含 markdown 的 `知识库/`），导致 `loadPreset`/`step2CoolingCheck` 读不到文件。改为用 `PROJECT_PATH` 反推 InkWeave 根（`path.resolve(PROJECT_PATH,'..','知识库',...)`），**源码与 dist 双正确**。这是预存在隐患，本次暴露并修复。

## 三、关键发现（这条值钱）

**R4"胜出版"第14章（视觉 68/152≈44.7%，勉强过 45% error 线）但 触觉 35 < 视觉 68，违反预设"触觉≥视觉"。** 这条约束之前完全隐形（检测器只数触觉不校验），现在作为 warning 浮出——证明即便"99分A级"章，也不满足预设自身的感官均衡要求。预设约束终于开始"说话"。

## 四、残留 / 下一步（不在 v1 范围）

1. **多样性是"软轮换"**：step0 给出每章主导感官/修辞变奏提示，仍靠 LLM 自觉。要硬，需像排比那样在检测器加"非视觉感官多样性"校验（v2）。
2. **信息密度（每1000字≥4信息点）只作生成目标，检测器未强制**——可靠检测较难，暂留。
3. **锚点密度/触觉<视觉 当前是 warning 不是 error**：v1 刻意不立刻加硬阻断（避免旧章全崩），等生成真产出达标文本后再升 error。
4. **效果度量**：v1 建立了机制，但"文风多样性确实提升"需小样本盲评证明（路线图 #5，卖课弹药）。
5. **预设切换**：目前只接了 裂日 的 都市异能-番茄 预设；其他书/其他预设（如 荒古纪元 的玄幻）走同一套代码，未逐一验证。

## 五、对 skill 能力的影响

- **之前**：生成只用 `生成指令.md` 的通用硬编码铁则，22 节点 + 18 预设是沉睡的参考资料。风格切换是假的。
- **现在**：① 绑定预设真正注入生成（核心指令/约束/专属词汇）；② 预设特有的"触觉≥视觉""锚点密度"从空话变真检查；③ 每章按章号强制多样性轮换，直接对抗"堆砌递进体"单调。
- 这是"判卷老师"向"出题老师"迈的第一步——生成端开始被主动塑造，而非只靠写完后拒收。
