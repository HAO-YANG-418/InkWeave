## 一、口语化不足 · 根因（实证）

### 1.1 真身证据：`opt_tone_colloquial` 只"允许"不"强制"
运行时默认语调节点（`dist/源码/kb/nodes/node_tone/opt_tone_colloquial.kb.json`）原文关键句：

- 用词层面：**"可以用适度口语词（知道/明白/搞/整/咋/啥），但不能满篇方言"** → 是「可以」，非「必须」。
- 句式层面：**"以中短句为主（15-25字），可以有断句、省略主语，但不能混乱"** → 允许断句，未要求口语连接。
- 禁止事项：**禁止文艺腔（'彼时''忽而''颔首''蹙眉'）、禁止翻译腔、禁止书面语堆砌** → 只禁了**表面文艺词**，**没禁书面联接词**（因此/然而/继而/况且/换言之/总而言之/与此同时）。

**结论**：该节点是"软声明"。它声明了"口语白话"的意图，但没有任何一条把口语**装成硬约束**——不要求语气词密度、不提供口语范式、不禁止把半书面联接词当过渡。模型读到的信号是"尽量口语，但不强制，别太方言"。

### 1.2 其他默认节点把语域往上拽（合力半书面）
| 默认节点 | 真身措辞 | 对语域的影响 |
|---|---|---|
| `opt_sentence_rhythm_mixed` | "用1-3句长句（40-60字）把氛围铺足" / **"要紧张的时候，句子越来越短，段落越来越碎"** | 鼓励 40-60字长句铺陈（文学化）+ 紧张场景主动"碎" |
| `opt_desc_sensory` | 五感写作要点，全是形容词/名词精细描写（暗红/铁锈红/甜腥） | 沉浸但把 register 往上提，偏文学描写 |
| `opt_rhetoric_plain` | "不刻意使用比喻" | 平实但**无口语正向**——只是"不用修辞"，不等于"用口语" |
| `opt_paragraph_density` | "50-120字" | 与产出大量 5-15字段落冲突（见 1.4） |

**合力**：tone 弱允许口语 + rhythm 推长句铺陈 + sensory 推文学描写 → 模型落地在**半书面叙事 + 口语词点缀**的模糊中间带。这正是用户感受到的"不够口语化"。

### 1.3 一句话根因
> **去冷峻 ≠ 装口语；允许 ≠ 强制。** 我们 earlier 只把 `serious→colloquial` 换了默认，但 colloquial 种子是"软声明"，压不住基础模型内在的半书面语域。等于拆了"禁止冷峻"的墙，没建"强制口语"的墙——模型滑回它默认的半书面。

（这与阶段认知"约束只配排错、不带来提升"同构但反向：删坏约束不会自动长出好声音，好声音必须**正向安装**。）

### 1.4 碎片化（"塞回口袋"所在的碎段）是两个原因叠加
- **引擎侧**：`opt_sentence_rhythm_mixed` 第6条明写"紧张的时候，段落越来越碎"——主动鼓励一句一段。
- **我（agent）侧**：本轮为过检测器 + 强开场，把句子越剁越碎（终稿 61.7% 短句、123→75段落仍是碎片感）。
- 两者都让"口语"变"剁碎"：**真口语是连成一气的短句（'许照把刀折了塞回兜里，又蹲回国庆跟前，盯着那片暗红看了会儿'），不是一句一段的断奏。**

### 1.5 实例对照（用户点名的"塞回口袋"）
| | 原文（半书面） | 口语化改写 |
|---|---|---|
| 句 | "许照把刀折回去，塞口袋。蹲回陈国庆面前，看那片不渗血的暗红。" | "许照把刀折了塞回兜里，又蹲回国庆跟前，盯着他那片不渗血的暗红看了会儿。" |
| 差异 | 口袋/面前/看那片…暗红 = 中性书面词 | 兜里/跟前/盯着…看了会儿 = 口语词 + 口语动宾 |

根因可见：模型用了**中性书面形**（口袋、面前、看那片…暗红），而口语形（兜里、跟前、盯着…看了会儿）在 colloquial 节点里"可以"用却没被推向。

## 二、生成时延 · 根因（讨论）

### 2.1 skill 阶段这次"慢"是我（agent）的锅，不是引擎
本轮出文 = 我手写的盲写 + 多轮"写→检测器→改"循环（7→3→1→0 错误，约 8 轮工具调用 + 抽底座 + 读文）。**这是 agent 工作流开销，不计入引擎指标**——引擎现在根本没跑 LLM（阶段边界：不接 API）。

### 2.2 引擎真实时延的驱动因子（软件化阶段才会暴露）
从 `源码/writing/engine.ts` 管线看，一章 = LLM 调用若干次：
- `draft`（≈2200字，一次 chat completion）
- `revise templates`（按冷却检测改，一次 LLM 调用）
- `finger-print inject`（一次 LLM 调用）
- 检测器每轮 `npx tsx` 独立进程冷启动（≈1-2s + 编译）

**关键洞察：revise 轮数 N 由"底座强弱"决定。** 底座弱 → 首稿过不了检测器 → 多轮 revise → 既慢又碎。本轮"碎"和"慢"在引擎侧会是**同一病根的不同症状**。

### 2.3 其他时延风险
- `npx tsx` 每轮冷启动：应改为常驻服务或预编译（`tsc` 一次后 `node dist`）。
- `ai_continue_length=medium`（500-800字/beat）：若按节拍流式生成，调用数 ×4~5，可控性高但更慢；整章一次生成更快但易失控。
- 多节点 config 加载 + 指纹注入反馈环：若每章都重算全部 KB，有冗余可缓存。

### 2.4 一句话结论
> **弱底座同时害了口语 + 时延。** 强化口语种子 → 首稿即过检测器 → revise 轮数↓ → 又快又口语。两件事是同一个修法，不是两件事。

## 三、修复路径讨论（待用户拍板）

| 路径 | 做法 | 能解决 | 局限 |
|---|---|---|---|
| **A（推荐·skill阶段可做）** | 强化 `opt_tone_colloquial` 种子：①「可以」→「必须」+ 列禁用的书面联接词（因此/然而/继而/换言之/与此同时）②要求语气词密度（了/吧/嘛/呗/啥）③给口语范式+反例 ④把 rhythm 节点"紧张时段落越来越碎"改为"短句但连成段，不拆一句一段" | 口语化根因 + 间接降时延 | 仍靠 prompt，强模型才稳；最狠的口语需权重 |
| **B** | 检测器加"书面联接词密度""语气词缺失"检查 | 兜住书面残留 | 记忆铁律：检测器只配排错，不带来提升；且每轮检查加冷启动成本 |
| **C（软件化阶段）** | 微调（fine-tune）在热门网文口语语料上，把口语压进权重 | 最根治 | 需跨阶段 + 用户给 provider/model |

**我的判断**：A 是现在就能落、且不碰 API 的真杠杆；B 配合 A 做安全网；C 是终极解留软件化。A+B 先上，能立刻让"塞回口袋"这类半书面消失、且减少 revise 轮数。
