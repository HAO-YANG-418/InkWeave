# 回归验证 · Item 1 检测器落地（对话碰撞 + 主角私心驱动）

> 起草：代码方（2026-08-27）。依据方案方 `检测语义方案_对话碰撞与私心驱动_2026-08-27.md`。
> 背景：#65 铁则二十一落地后，生成侧已强制「对话有火花 / 主角有私心」，但检测侧无对应 ruleId。等长复验（§七）进一步暴露：旧 `对话缺乏碰撞` 检测器**依赖引号**才能识别对话，对无引号风格（引擎真实可能输出）是盲区——after_v2 无引号对话被识别为 `对话0段`，警告"消失"实为检测器看不见对话。本验证补两个检测器并坐实盲区已修复。

## 一、落地内容（双树）

### 1. `dialogue_conflict`（对话缺乏碰撞）—— 增强生成树，修复引号盲区
- 文件：`源码/checker.ts` `checkDialogueConflict`（原 line ~1057）
- 原逻辑：仅用引号正则提取对话 + `stats.dialogueRatio < 0.05` 跳过 → after_v2 无引号 → 直接跳过，盲区根因。
- 新逻辑：**引号 + 无引号双通道**。无引号通道用「角色名 + 言语动词（说/道/问/开口/插话…）」锚点式提取整段话语（锚点→下一锚点/段末，允许多句，避免截断漏掉反对词）。跳过条件从 `dialogueRatio<0.05` 改为「轮次 < 4」（独白/内心章豁免）。
- 沿用原 ruleId `dialogue_conflict`，不新增 ruleId，避免双树重复扣分（生成树为权威源，CLI 门禁经 R1 聚合已可见）。

### 2. `protagonist_stakes`（主角工具人）—— 新增 CLI 树正则检测器
- 文件：`检测工具/checkers.ts` `checkProtagonistStakes` + 注册于 `结构密集型` 组
- 逻辑：主角名 + 0~20 字内出现私心动机词（家人牵挂/恐惧/利己抉择/未竟执念）→ 通过；否则报 `主角工具人`（warning）。
- 护栏：章节根本不出现主角名 → 跳过（防非本作章节每章误报）。

## 二、代码方三点决策（方案 §五 拍板）

| # | 决策点 | 代码方决定 | 理由 |
|---|---|---|---|
| 1 | `protagonist_stakes` 默认 warning 还是 error | **warning** | 新检测器先观察误报率，不急 error 逼重写；与"先跑量再调参"一致。error 升级留作选项。 |
| 2 | LLM 语义层落 `源码/checks/` 还是 CLI 树 | **LLM 版按方案 §三方向预留于 `源码/checks/`**（复用 `check-semantic-smoothness` 的 `llm-helper` 通道）；但 CLI 门禁走**同步 `check()` 链路、LLM 属 async reflection 不参与门禁** → 本次验收用 **CLI 树同步正则版**作权威门禁判定。LLM 版作生成时 async 自纠增强，留接口不阻塞。 | CLI 门禁必须离线、同步、可回归；正则版已满足"门禁可拦 + 回归可验"。 |
| 3 | 说话人正则上限 1-4 字是否覆盖本作 | **放宽为 {1,6}** | 林深/赵明远/周野/林浅/老周均 ≤3 字，{1,6} 覆盖有余并容更长称号；≥7 字叙述句排除。 |

## 三、两处假阳性修复（诚实记录）

1. **无引号长片段误吞单字反对词**：锚点式提取会吞入叙事，单字反对词 `停`（"脚步没停"）在 before 误判为碰撞，使 before 假通过。修复：无引号轮次**仅用 ≥2 字强反对词**（排除 `错/停/滚` 等单字），引号轮次仍用完整词表。after_v2 的碰撞靠多字「不是」保留。
2. **私心词 `报` 歧义**：单字 `报` 与 before「赵明远**报**坐标」误撞（报告≠报仇）。修复：从私心词表移除 `报`。before 实际 `阿苓=0`（确无私心）→ 正确报 `主角工具人`。
3. **跨项目假阳性**：硬编码 `林深` 会使非裂日章节每章误报 `主角工具人`。修复：章节不含主角名则跳过。

## 五、已知限制（不美化）

1. **无引号对话的"无言语动词直接引语"仍部分漏检**：本作 after_v2 多为"角色名+动作/心理，然后直接说话无动词"（如「周野从副驾回头，眼神钉他。你尝到什么。」）。当前正则要求"角色名+言语动词"前置，这类纯靠上下文的对话未被捕为轮次。v1 靠"言语动词锚点"覆盖主要碰撞（line71「赵明远说…不是慈悲」已命中），但更隐蔽的无动词对话需 LLM 语义层（决策 2 预留）才能完整覆盖。
2. **`protagonist_stakes` 主角名硬编码 `林深`**（v1），待接入 kb 配置（CLI 树执行器 `checkChapterGrouped` 仅传 text/stats，不传 thresholds）。
3. **LLM 语义层未实现**（决策 2 明确本次不阻塞）：`源码/checks/` 通道已具备（`llm-helper`），生成时 async 自纠增强待后续接入。
4. 两检测器均为 **warning 级**，不阻断门禁（与"先观察再升 error"一致）。
