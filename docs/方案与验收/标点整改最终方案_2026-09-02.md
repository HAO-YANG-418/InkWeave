## 0. 一句话结论

标点问题（尤其破折号）**不是模型笨，是规则没拉齐、没硬到底**。模型是概率机，标点只是 token，没有"对错"概念；破折号在训练语料里高频、与引擎原"文学极简/留白"美学同向，模型默认爱用。我们虽有"禁止破折号"的意图，但**禁令只写在了半套地方，且检测器放行 ≤2 个**——等于没禁。本方案把口径统一成"硬禁 + 双保险"。

## 1. 为什么标点会出问题（根因·机制）

1. **模型 = 概率机**：每写一个字/标点，都是在算"这个位置最像训练数据的下一个 token"。标点（"的""了""，""——"）对它都是 token，**没有"该不该用"的判断，只有"像不像"的概率**。
2. **破折号训练先验强**：网文/翻译体/文学小说大量用"——"做戏剧停顿、内心独白，模型学到"用破折号 = 有文采"。不拦就顺着概率冒。
3. **引擎原设计与先验同向（坑点）**：引擎最早美学是"文学极简/冷峻/留白"，与破折号的"文学感"同一方向 → **等于鼓励**模型用破折号。
4. **禁令只写半套 → 口径打架 → 模型挑最强的走**：`base` 说禁、`tone` 节点说"可以用"、检测器说"放行 ≤2"，三处不一致，模型自然走它最舒服的那条（破折号）。

> 所以"必须用规则约束"是对的，且要**双保险**：提示词规则（事前把分布往合规推，但不 100% 听话）+ 检测器（事后兜底，破折号必须硬禁 error 才有效）。

## 3. 最终整改方案（含 file:line + 改法）

### P0（阻塞"禁用破折号"有效性，必须做）

**P0-1① 破折号检测器升硬禁**
- 位置：`检测工具/checkers.ts:381-393`（"破格额度"段，注释明写"对铁则十二零容忍的人性化修正，完全零破折号会制造太干净没个性的均匀腔"）
- 改法：**删除"每章 ≤2 处允许"逻辑，改为出现 1 个即 `severity: 'error'`**，ruleId 保留 `forbidden_char_dash`。`autoFix:1873`（全替换逗号）保留。
- 说明：此段是有意设计，本次按你"禁止破折号 / 需要用规则约束"的拍板**推翻该人性化修正**，统一到硬禁。

- 位置：`源码/kb/presets/preset_base_webnovel.json:80`（`no_dash` 规则 `severity: "warning"`）
- 改法：`warning` → `error`，与硬禁对齐。

**P0-1③ base 铁则补"零容忍"措辞**
