## 五、暴露的两个真 bug（需代码方修）

### BUG① 章号解析串文件（CLI 体验缺陷）
- 现象：`check 26`（用章号）未命中"第26章 收种.md"（9318 字节），误读到一个 320 字损坏/测试残留（18 处重复段落 + `"stateHints": []` JSON 残留，评分 0/100）。
- 根因：`resolveChapterPath` 章号正则匹配不稳（可能命中 `_archive` 或其他前缀文件）。
- 规避：用完整文件名 `'第26章 收种.md'`（--project 模式不带路径前缀）才正确。
- 影响：用户按章号跑 check 会拿到错误报告，误判章节质量。

### BUG② 锚点口径不一致（检测可信度缺陷）
- 现象：同章基础统计"身体锚点 = 49"，但锚点检测器报"当前锚点数 0 / 密度 0.0 / 间隔 3114 字"。
- 根因：CLI 树锚点检测（`checks/check-data-anchor` 或 `checkers.ts` 锚点段）与基础统计 `countAnchors` 口径不同（认锚点的正则标准不一致）。
- 影响：同一章锚点既报 49 又报 0，直接拉低评分可信度。

## 六、硬卡点：生成新初稿跑不了

- `.inkweave/` 缺 `llm.json`（真实 LLM 配置，仅 `.example`）。
- `gwe-engine` 调 LLM API 需要 `apiKey`，缺则**完整"写前分析 → 生成 → 双树检测 → 反射重写"闭环缺生成侧**。
- 当前可纯本地跑：pre-analysis（写前分析）、check（检测）、verify-regression（回归）等；**生成（quick-write / gwe-engine）卡住**。

## 七、结论：初稿问题到底能不能解决

| 层面 | 状态 |
|------|------|
| 写前分析（机械约束注入） | ✅ 真跑通，反向闭环生效 |
| 双树检测（拦 AI 味/空洞/字数） | ✅ 真跑通，能抓比喻堆砌/感官失衡/字数差 |
| 节点配方生成文风 | ✅ 真实产出有文风（冷峻白描触觉密集） |
| 单章直接交稿 | ❌ 33/100（D级），需重写循环把分从 33 拉到 ≥85 |
| 端到端"生成→检测→重写"闭环 | ⚠️ 卡在 LLM key，无法实测"初稿自动达标" |

**回答用户原问**：机制**能**解决初稿问题（质检侧已就位、配方能生成有文风章节），但当前无 key 环境**无法端到端实证"自动解决"**；且单章直接交稿仍差一个"重写循环"，而该循环 = 生成侧，正卡在 key。另有两个检测 bug 需修才能信评分。
