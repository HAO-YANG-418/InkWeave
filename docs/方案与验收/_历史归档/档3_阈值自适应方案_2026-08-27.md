## 二、⚠️ 架构真相告警（关键，必须先报）

用户原设想「档3 = 调 `Thresholds`（kb 管道 `threshold_overrides`）」，但核真身两棵树阈值来源不同：

- **源码树**（`源码/checker.ts` + `源码/checks/`）：`check(text, null, R1_MERGED_CONFIG, targetWords)` 读 `Thresholds` 类型；`config-merger.ts:129` 第4层从 kb `threshold_overrides` 灌入。**→ 这套可调、走 kb 管道、不动 .ts。**
- **CLI 树**（`检测工具/checkers.ts`）：warning 阈值**硬编码**（grep 全库仅 line 250 一处提 thresholds；执行器 `fn(text, stats)` 不传 thresholds）。**→ 调参必须改 `checkers.ts` 源码常量（.ts，代码方）。**
- `check-chapter.ts:170/172` 双跑两棵树、warning 混合汇总进同一报告。

**结论**：调 `Thresholds` 只能治源码树那几个（碎句病/感官密度源码版/开头锚点/句子过长等）；**十章 warning 大头**（质感多样性 7/10、感官密度 4/10、角色台词差异化 9/10、读者负担 5/10、碎句 CLI 版 4/10、排比 1）全部在 **CLI 树硬编码**，调 `Thresholds` 治不到。这是认知与架构偏差，必须决策（见第七节）。

## 三、分树分类（哪些该调 / 哪些保留）

- **对话缺乏碰撞** 9/10：Item1 检测器正常报警（before 未重写），调松=自我推翻。
- **主角工具人** 5/10：Item1 检测器正常报警。
- **角色台词差异化** 9/10：真问题（角色声音无差异）；且与 Item1 同源依赖引号（dialogueRatio<0.05 跳过），属**检测器增强**范畴（不依赖引号），非阈值微调能解。

### B 类 · 设计内放行提示（用户 trea 铁则「不硬凑」）
- **字数偏少** 10/10：CLI 树 `checkWordCountTarget`（检测工具/checkers.ts:1199）「短而密放行」warning——密度达标即放行，符合不硬凑。可选：短而密干脆不警告（降 info 或移除）。

### C 类 · 系统级误伤 / 口径偏紧（聚焦用户点过的，可调）
- **碎句** 4/10：需区分 CLI 树 `short_sentence`（鼓点短句误伤源）vs 源码树 `fragmented_sentences`（碎句病，较准防段内连续短句）。
- **质感多样性** 7/10：用户点过"凉循环"，冷感基调章合理复用被误报。
- **感官密度** 4/10：短章密度天然低，但内容精炼。
- **开头缺少身体锚点** 6次/3章：每章报 2 次同类型，疑似段落级重复计数误伤。
