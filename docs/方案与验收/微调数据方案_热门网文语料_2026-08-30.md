# 微调数据方案 · 热门网文语料（好懂基准）

> 配套决策：「解决 skill 烂 = 走微调（fine-tune）」路径（2026-08-30 用户拍板）。
> 本方案只动**数据 + 预处理脚本骨架**，不碰权重、不花钱。权重训练由代码方在拿到语料 + 底座后执行。
> 前置方向钉死：`网文可读性基准_覆盖晦涩极简偏差_2026-08-30.md`（错靶 = 文学极简/克制/留白/低逗句比被误当写作好）。

---

## 一、目标与边界（先说清能改什么、改不了什么）

**微调能改的**：文笔质感 / 网文语感（行文像不像好网文、通不顺、好不好懂）。
**微调改不了的**：剧情结构、章法推进、人物弧光——这些是**大纲层**的事，与权重无关。
**真解（已拍板）**：`微调(文笔语感) + 硬大纲(结构)` 双管，非微调单吃。

**两侧同步铁律**：单改 prompt 不拆晦涩种子 → 模型滑回文学腔；单微调不拆种子 → prompt 把你拉回。
本方案产出的语料必须是「好懂直白」的热门网文，与 `生成指令.md` / KB 节点 / `裂日.config.md` 的降级改动**互为表里**。

---

## 二、语料选择原则

1. **好懂优先**：选「读者零理解负担」的直白流作者，**排除文青/晦涩向**（猫腻、烽火戏诸侯、烟雨江南等——文风偏文气，微调进去反而带晦涩风险，与本次目标相反）。
2. **genre 贴合 + 通用兼顾**：裂日是「都市异能/悬疑」向，优先取同 genre 顶流；同时补经典标杆保证语感通用，不塌成一本书的影子。
3. ** popularity 锚定**：以起点收藏榜 / 畅销榜实据为准（2026-08 检索：诡秘之主收藏 1948万 #1、灵境行者 1446万 #2、斗破苍穹 1259万 #3、大奉打更人 983万 #8；捞尸人当期月票 #1）。
4. **正版合规**：语料须来自用户已购/已授权文本或平台合规 API；脚本不内嵌任何盗爬逻辑。

## 三、训练样本 Schema（OpenAI chat/completions 格式）

引擎是 OpenAI 兼容 `/chat/completions`（`源码/llm-provider.ts` 已核真身），微调数据即标准 `messages` 数组。
**不要只喂 raw 正文**——那不是小说生成的良构监督。应构造 `(写作情境 → 好懂正文)` pairs，让权重学「给情境产出好懂网文」。

```json
{
  "messages": [
    {
      "role": "system",
      "content": "你是网文作者。第一标准是好懂：读者零理解负担。简约≠难懂，克制≠不说清，留白≠藏逻辑，低逗句比≠剁碎句。写清因果与关键事实，用具体动作/感官/对话推进，不注水。"
    },
    {
      "role": "user",
      "content": "【章节简报】意图：压力镜头；核心冲突：名单上没有林深的名字；开头：感官轰炸；钩子：划掉的名字墨迹未干。\n【前文末段】……\n【约束】都市异能向，直白流畅，每章≥3000字。"
    },
    {
      "role": "assistant",
      "content": "（从语料切片 + 同构重写得到的「好懂网文正文」段落）"
    }
  ]
}
```

**两种样本形态（混合用）**：
- **A. 续写型**（主）：`user` = 前文 N 段 + 章节简报；`assistant` = 后续正文段。让模型学「接住上下文写出好懂网文」。
- **B. 指令型**（辅）：`user` = 纯章节简报/约束；`assistant` = 整章正文。强化「按指令产出好懂文」。

**assistant 正文来源**：从选定语料按场景切片得到的原文段落（保留原作好懂语感），**不**用引擎现产（现产正是要被修的）。若做「同构重写」增强泛化，由人工/强模型在保留语感前提下改写，禁止引入晦涩。

## 四、扒 → 洗 → 切 预处理流程

### 扒（获取，合规）
- 输入：每本书一个 `corpus/<书名>/raw.txt`（用户已授权文本）或经平台 API 拉取。
- 脚本**不**含任何网络爬取；只消费本地已就绪文本。

### 洗（清洗）
1. 去版权页 / 目录 / 上架感言 / 作者说 / 月票求票等非叙事块。
2. 去乱码、全角半角归一、合并被换行切断的句子。
3. 段落以空行切分；章节标题（如「第N章 xxx」）单独标记。
4. 统一标点到中文全角（，。！？「」——），但**保留原作逗号连写节奏**（不预切句，避免破坏语感）。

### 切（切片成训练单元）
- 按「章节 → 场景」两级切。场景以空行 + 视角/时空切换为界。
- 每个训练单元 = 一个场景（建议 300–1500 字；超长按镜头再切，过短合并相邻场景）。
- 构造 pairs：取场景 i 作 `assistant` 目标，场景 i-1（+简报占位）作 `user` 上下文；整章模式则整章作 `assistant`。

### 质量过滤（关键，防喂回晦涩）
- 用引擎现有雷达/检测器（`源码/radar.ts` + `源码/checks/`）对候选段跑分：
  - 剔除「信息密度低 / 注水 / 碎句率过高（无身份碎句）」样本；
  - 剔除「需回读才懂」的晦涩段（人工抽审 5%）；
  - 诡秘之主类高密度样本限比例 ≤ 15%。
- 去重：相邻章节重叠上下文做 hash 去重，避免过拟合。

### 导出
- `train.jsonl` / `val.jsonl`（9:1 切分），每行一条 `messages` JSON。
- 建议量级：5k–20k 高质量样本起步；genre 配比见第二节。

## 五、训练侧（代码方执行，本方案不实现）

1. 底座：引擎 `源码/config.ts` 支持 `deepseek`/`ark(豆包)`/`openai`/`custom`/`mock`。微调完填 `CUSTOM_BASE_URL` + `CUSTOM_MODEL` 即换底座，`.ts` 不动架构（已核真身）。
2. 实际 provider/model 由用户报（仓库仅 `.example.json`，key 走环境变量，反推不出）→ 决定走厂商微调 API 还是本地开源权重端点。
3. 训练代价口径（事前评估）：默认扫 10 章、每章 1 次调用量级；若抽 3–5 章样本先跑，成本更小。非无底洞。

## 六、诚实边界 / 风险

- 微调**救不了结构**：章节推进/赌注/钩子/情绪靠大纲与写前简报，权重改不了「这一章发生什么」。
- 语料若混入文青/晦涩样本，会污染「好懂」目标——第二节红线必须守住。
- 数据量不足（< 2k）易过拟合单书语感；建议 ≥ 5k 且 genre 分散。
- 本方案 + 脚本骨架交付后，真实训练需算力/API 额度（软件化阶段任务，非内部 skill 轮范围）。
