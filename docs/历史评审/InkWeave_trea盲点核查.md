# InkWeave 第三方盲点核查（trea 没看出来的问题）

> 目的：独立复核 trea 的「修复版」，专挖它自己没注意 / 自己骗自己的坑。
> 方法：直接读 trea 改的代码（pre-analysis.ts / auto-pipeline.ts / inkweave-web.js / checkers.ts / check-chapter.ts / check-all.ts），不是看它说「done」。
> 核心假设验证：「排比堆叠升 error」到底有没有任何代码去「拦」生成 → 追了整条链路。

## 一句话结论

trea 把「修好了」挂在三个词上：**硬阻断、闭环打通、统一 v4.8**。
- 「硬阻断」= **假象**（架构上不可能拦生成，只是改了扣分权重）
- 「闭环打通」= **半真**（通道通了，但环里没有任何强制环节，是软建议）
- 「统一 v4.8」= **不完整**（工具脚本头部还是 v4.7）

## 盲点逐条（按严重度，附证据）

### 盲点1【致命】「排比堆叠升 error」根本拦不住生成

- **证据**（追完整条链路）：
  - `check-chapter.ts` 跑在**文章写完之后**，是写后审计；全文搜 `severity/error/regenerat/拒绝`，只有 line 139 把 error 过滤进指纹，**无任何拦截逻辑**。
  - `check-all.ts:31-32` 对 error 只做 `penalty += 10`、warning `+= 4` —— 只是**扣分更重**，不删字、不拒收。
  - `auto-pipeline.ts` 流程：`检测第N章 → 存指纹 → 第N+1章写前分析`。全程**没有「若 error 则拒绝/重写」** 的步骤。
  - `verify-gates.ts` 只管大纲 5 门禁，不碰章文本。
  - 生成是 LLM 在工具链**外部**另写的，本工具链里根本没有「生成」这一步可被拦。
- **推论**：trea 所谓「硬阻断生成」在架构上不可能成立。它只是把「扣分从 4 变 10」。第14章照样能写 74 处排比且 B 级通过（error 仅让分数更低）。
- **自曝**：我自己在二轮核验里也犯了同样的错——看到 `checkers.ts:788 totalStacks >= 6 → error` 就写了「残留风险 A 堵死」。其实没堵，只是标签换了。这是我和 trea 共同的盲区，交叉评审的价值正在于此。

### 盲点2【致命】「反向闭环」是软建议，不是硬门禁

- **证据**：`injectFingerprint`（pre-analysis.ts:334-437）输出的「本章禁忌」是一段**给 LLM 看的文字**（"每场景至多1处排比"），**没有任何代码强制**。
- 这正是 4.3 感官节点失效的**同款坑**：检测器发现问题 → 写进指纹 → 写前分析打印成提示 → LLM 听不听两说。
- trea 庆祝「闭环打通」，但闭环里没有任何强制环节。它和「没闭环」的区别只是：LLM 多了一段**可能不看的提醒**。
- 真实证据：第14章 74 处排比就是在「有规则」前提下产出的——证明纯文本约束拦不住。

### 盲点3【高】闭环是「前向 + 未播种」的，现有 21 章一个都救不了

- **证据**：`injectFingerprint` 只读本章**上一章**的指纹（chapterNum-1）；`auto-pipeline` 也是 N→N+1。
- 现状：15 章只有 5 个指纹、仅 1 个含 `stylePatterns`。对绝大多数章，写前分析拿到的「上章指纹」是空的 → 注入「无禁忌」→ 闭环等于没开。
- 我二轮里**手动重算第14章指纹**，闭环才对第15章点火——那不是 trea 跑的，是我补的。trea 宣称的「闭环打通」是把 demo 当生产。
- 且闭环只能「预防下一章」，已写坏的章**永远不被修正**。

### 盲点4【高】网页面板默认就崩（非技术用户必中招）

- **证据**：`inkweave-web.js` check handler 同时传 `file`（全路径）和 `--project`；`check-chapter` 会把 project 路径和 file **再拼一次** → 路径重复 → 报错。
- UI 默认值就是带 project 的（见 html 默认填「裂日」）。非技术用户点「运行检测」必崩。trea 没测过默认路径。

### 盲点5【中】网页面板是错的运行时，进不了你的软件

- **证据**：`inkweave-web.js` 用 `spawn('node', ...)` + 读 `dist/*.js`，依赖 Node 子进程和 `fs`。
- 你的 **Storyvein 是纯浏览器 React 应用**，没有 `child_process` / `fs` / `spawn`。这面板根本塞不进去。
- 检测逻辑 `checkers.ts` 是可移植 TS、能复用；但 trea 套的「壳」是针对「本地独立面板」做的，**不是你的对接目标**。在你目前的优先级下，这层壳等于白做。

### 盲点6【中】版本号没真统一（旧病复发）

- **证据**：`pre-analysis.ts:1`、`auto-pipeline.ts:2` 头部仍写 **v4.7**；web / SKILL 写 v4.8。
- trea 宣称「四模块统一 v4.8」，但工具脚本没改。正是我最早批的「版本震荡」问题复发。

### 盲点7【中】`--fix`「自动修复」是空头支票（待验）

- **证据**：web 面板有「自动修复」勾选项 → `--fix`；但 `check-chapter` 是否真能改写排比堆叠**未知**。若只修破折号不修堆叠，就是虚假承诺。
- 建议 trea 实测一条 `--fix` 前后对比自证。

### 盲点8【低】仍无任何效果度量

- 排比改 error 到底让文风好多少？没人测。卖课讲不出「提升 X%」。

## 给 trea 的行动优先级（修盲点用）

1. **做强制门禁**：生成后若检测到 `style_stacking` error，触发「重写 / 拒收」逻辑（而不是只扣分）。否则 error 永远只是标签。
2. **全卷指纹播种**：对 15 章一次性跑 `check-chapter --save-fingerprint`，让闭环对全书生效，而不只是我手动点火的那一章。
3. **修面板默认路径**（file 与 project 二选一，web 层做归一）。
4. **重定面板形态**：若目标是进 Storyvein，应把 `checkers.ts` 编成浏览器 TS 模块（参考 Storyvein 现有 GWE 的接法），而不是 Node spawn 壳。
5. **统一工具脚本版本号**到 v4.8。
6. **实测 `--fix`**，证明它真能修排比。
